## 報告された症状

実際の会議音声（約25分）の出力に、以下が確認されています。

### 単語の途中で話者が切り替わる

```
SPEAKER_00: 全部終わったら
SPEAKER_04: まと        （0.23秒）
SPEAKER_01: めて        （0.25秒）
SPEAKER_00: たらします
```

**「まとめて」という1語が3話者に分割されています。**言語的にありえません。

同様の例:

- 「承知いたしました」→ SPEAKER_00「承知いた」/ SPEAKER_03「しました」
- 「皆さんお揃いですか」→ SPEAKER_00「皆さんお揃い」/ SPEAKER_01「ですか」
- 「桐山さんわかんないです」→ SPEAKER_01「桐山さんわかん」/ SPEAKER_04「ないです」

### 時刻そのものが壊れている箇所がある

```
536.88 - 558.55  UNKNOWN「ご視聴ありがとうございました」   21.67秒
1369.24 - 1378.49  SPEAKER_03「そう」                      9.25秒
1378.49 - 1387.72  SPEAKER_00「です」                      9.23秒
```

**「そうです」の3文字に18.5秒**が割り当てられています。
「ご視聴ありがとうございました」は無音区間でのハルシネーションと考えられます。

## 原因の構造

**2層に分かれます。順序を守って対処してください。**

```
[第1層] ASR の時刻が壊れている
   ↓ ここを直さないと、下流の調整は対症療法になる
[第2層] 話者割当が瞬間的な判定を信用しすぎている
   ↓
[第3層] 品質を数値で測る手段がない
```

## P0-2 — 話者割当を系列全体で最適化する

### 現状

`src/utteran/align.py` の `assign_word_speaker()`（103-126 付近）は、
**1単語ごとに独立して**話者を決めています。

```
中心時刻が話者区間内 → その話者
  ↓ なければ
最大 overlap の話者
  ↓ なければ
最近傍の話者（既定 2.0 秒以内）
```

`_split_segment_by_speaker()`（129-165 付近）は、
**話者が変わるたびに即座にセグメントを分割**します。

**瞬間的な判定を 100% 信頼しているため、
0.2 秒の揺らぎがそのまま出力に現れます。**

### 改修方針

**Viterbi / 動的計画法により、系列全体で最適な話者列を求めてください。**

考え方は以下です。

| 要素 | 内容 |
|---|---|
| emission score | 各単語と各話者区間の重なり時間に基づくスコア |
| transition penalty | 話者が切り替わることへのペナルティ |
| 最適化 | 系列全体でスコアが最大になる話者列を選ぶ |

これにより、`00 → 04 → 01 → 00` のように **0.5 秒以内に2回切り替わる系列**には
強いペナルティがかかり、選ばれにくくなります。

### 設計上の要点

**1. ペナルティを一律にしないこと**

以下の場合は、切り替えのペナルティを弱めるべきです。

- 単語間に十分な無音がある
- 話者区間の境界と明確に一致している
- 単語の重なりスコアの差が大きい（明らかに別話者）

**逆に、以下では強めるべきです。**

- 単語間に間がない（連続発話）
- 重なりスコアが拮抗している

**2. 短い相槌を消さないこと**

「はい」「そうですね」のような**本物の短い発話**は保持する必要があります。
ペナルティを強くしすぎると、これらが吸収されます。

**Phase 3d と長時間音声の調査で、「粗すぎ」と「細かすぎ」の
両極を経験しています。**その中間を狙ってください。

**3. パラメータを設定可能にすること**

ペナルティの強さなどを `[alignment]` に追加し、
**既定値の根拠を実測で示してください。**

### 既存の後処理との関係

`align.py` には既に以下があります。

- 短い島の吸収（`A → B(短い) → A` のとき B を吸収。169-195 付近）
- 同一話者セグメントの結合

**Viterbi を導入した場合、これらの位置づけを整理してください。**

- 不要になるなら削除する
- 補助として残すなら、二重に効かないことを確認する
- **判断と理由を記録すること**

なお、現在の短い島の吸収は `A → B → A` にしか対応せず、
**今回の `A → B → C → A` を処理できません。**

## P1-1 — 最近傍フォールバックの見直し

### 現状

`assign_word_speaker()` の最終段は、どの話者区間とも重ならない単語を、
**最大 2.0 秒先の話者**に割り当てます（`AlignmentConfig.max_nearest_distance`）。

### 問題

**話者分離が「ここは発話ではない」と判定した区間**の文字にまで、
話者を付けてしまいます。

**無音でのハルシネーションが混ざる現状では、特に相性が悪い**です。
存在しない発話に、実在する話者の名前が付きます。

### 実施内容

以下を検討し、判断してください。

| 案 | 内容 |
|---|---|
| A | 重なりが無ければ原則 `UNKNOWN` とする |
| B | 両側が同一話者の場合のみ、短い間隔を橋渡しする |
| C | 距離の閾値を短くする |

**A + B の組み合わせが堅実**だと考えられますが、
**`UNKNOWN` が増えすぎないか**を実測で確認してください。

受入試験には「`UNKNOWN` の割合 20% 未満」という基準があります。

## P1-2 — 日本語における「単語」の定義

### 現状

`src/utteran/asr/whisper_cpp_words.py`（45-68 付近）では、
**CJK 文字を1文字ずつ独立した Word として扱います。**

```
「まとめて」→ ま / と / め / て  （4 Word）
```

一方、短い島の判定には `min_segment_words`（既定 2）が使われます。

**日本語では、この「words」が実質「文字数」になっています。**

### 実施内容

**話者境界の補正において、単語数より以下を重視してください。**

- 区間の長さ（秒）
- 話者区間との重なり
- 話者の切り替え回数
- 単語間の間隔

**文字数ベースの閾値を、そのまま使わないこと。**

設定名が誤解を招くなら、改名も検討してください
（互換性への配慮を忘れないこと）。

## P2 — 品質評価の基盤

### 現状の問題

受入試験は以下を測っています。

- 話者数、exclusive turn の存在、平均ターン長、
  最大話者の占有率、`UNKNOWN` 率、セグメント数/分、最長セグメント比率

**これらは「壊れていない」ことしか確認できません。**
「正しい人に正しい発言が付いた」かは測れていません。

**今回の「まとめて」問題は、すべての基準を通過します。**

### 合成音声による正解データ

**実際の会議音声は使わないでください。**
機密の問題があり、リポジトリに含められません。

**代わりに、合成音声で正解付きデータを作成してください。**

利点:

- 正解が厳密に既知（誰がいつ話したかを、こちらが決められる）
- **リポジトリに含められ、回帰試験に使える**
- 機密の懸念がない
- 問題のパターンを意図的に作れる

### 作成すべきパターン

**今回の症状を再現するデータを作ってください。**

| パターン | 目的 |
|---|---|
| 話者交代が単語の途中に来る | 「まとめて」問題の再現 |
| 短い相槌（「はい」「そうですね」） | **消してはいけないもの** |
| 話者の切り替えが密な会話 | 過剰な平滑化の検出 |
| 長い単独発話 | 過剰な分割の検出 |
| 無音区間 | ハルシネーションの検出 |
| 3人以上の会話 | クラスタリングの確認 |

**合成音声の作成手段は判断してよい**です（TTS、既存の音声素材の合成など）。
**リポジトリに含められるライセンスのものを使ってください。**

### 測定すべき指標

- **DER**（Diarization Error Rate）
- 話者境界の誤差（正解の切り替え時刻との差）
- **単語の途中で話者が切り替わった回数**
- 0.5 秒未満の話者切り替えの回数
- 1単語だけ別話者になった回数
- `UNKNOWN` の割合
- 短い相槌が保持された割合

**これらを受入試験のケースとして追加してください。**
