## 背景

### 現在の判断根拠が薄い

utteran は現在、以下の判断を**点の測定**で決めています。

| 判断 | 根拠 |
|---|---|
| auto が `vulkan` 優先 | 180秒での測定1点 |
| ovvk が長時間で有利 | 24分46秒での測定1点 |
| OpenVINO GenAI を採用せず | **参考実装での測定1点**（別実装、60秒、large-v3） |

**すべて点であり、面になっていません。**
しかも OpenVINO GenAI は utteran で一度も測っていません。

さらに Phase 3d で、**構成の優劣が音声長で逆転する**ことが判明しています。

| 素材 | Vulkan | OpenVINO+Vulkan |
|---|---:|---:|
| 180秒 | 15.4秒 | 19.6秒 |
| 24分46秒 | 110.7秒 | **65.1秒** |

**単一の測定では最適構成を決められません。**

### 目的

1. **バックエンドを跨いだ比較を、再現可能な形で行えるようにする**
2. **環境ごとの性能を、定量的な数値で示す**
3. 将来のバックエンド追加時に、同じ基準で評価できるようにする
4. auto 選択の根拠を、点から面へ変える

## 決定済みの仕様

**利用者との協議で確定済みです。変更しないでください。**

| 項目 | 決定 |
|---|---|
| **スコア** | **実時間比 × 100**（780 = 7.8倍速） |
| スコアの基準モデル | **large-v3-turbo に固定**（他モデルは参考値） |
| 測定内容 | **速度と精度の両方** |
| 実行時期 | 導入時は既定値。**後から最適化を促す** |
| 対象構成 | 選択可能。**動かない構成は提示しない** |
| 準備が要る構成 | 利用者に選ばせる |

### スコアの意味

```
スコア = 実時間比 × 100

100 = 実時間と同じ（1時間の音声に1時間）
780 = 7.8倍速（1時間の音声に約8分）
```

**環境を跨いで比較でき、直感的であることが要件です。**

**必ず併記すること:**

> このスコアは目安です。音声の内容、長さ、同時に動作する他の処理により変動します。
> スコアが2倍でも、処理時間が半分になることを保証するものではありません。

## 6a-1 — 測定対象の拡張

### 現状の制約

`run_benchmark()` は `variant` を受け取り、
`faster-whisper` なら `FasterWhisperBackend`、それ以外は `WhisperCppBackend` を使う、
という**2択の分岐**になっています。

```python
backend_name = "faster-whisper" if variant == "faster-whisper" else "whisper-cpp"
```

**バックエンドが増えると破綻します。**

### 実施内容

**バックエンドと構成を分離した表現にしてください。**

| 軸 | 値の例 |
|---|---|
| バックエンド | `faster-whisper` / `whisper-cpp` / （将来 `openvino-genai`） |
| デバイス・構成 | `cpu` / `cuda` / `openvino` / `vulkan` / `openvino_vulkan` |
| モデル | `large-v3-turbo` / `large-v3` / `medium` / `small` |
| 量子化 | `f16` / `q5_0` / `q8_0` |

**組み合わせを「測定対象」として表現し、レジストリから解決してください。**

**注意:**

- 既存の `--variants` オプションの互換性を保つか、判断して記録すること
- **すべての組み合わせが有効ではありません**
  （faster-whisper に `vulkan` は存在しない）
- 無効な組み合わせを弾く仕組みが必要です

### 実行可否の判定

**測定前に、その構成が実行可能かを判定してください。**

| 状態 | 扱い |
|---|---|
| 実行可能 | 測定する |
| **ハードウェアがない**（CUDA なし機で cuda） | **提示しない** |
| **準備が必要**（ネイティブビルド未実施、IR 未生成、モデル未取得） | **準備すれば可能と示す** |
| 判定不能 | 「不明」として扱い、「可能」と誤認しない |

**Phase 5k で実装したデバイス検出とキャッシュを使ってください。**
新たな検出機構を作らないこと。

**「準備すれば可能」の提示が重要です。**
現在 B-1 として「OpenVINO IR の導線が不明瞭」という課題があります。
ベンチマークが「IR を生成すれば速くなる可能性がある」と示せれば、
この課題も同時に解決に向かいます。

## 6a-2 — スコアの算出

### 速度スコア

```
速度スコア = 実時間比 × 100（整数に丸める）
```

- `realtime_factor` は既に算出済みです
- **基準モデルは large-v3-turbo**
- 他のモデルでの測定は「参考値」として区別する
- **測定条件を必ず併記する**（モデル、量子化、音声長、単語タイムスタンプの有無）

### 精度スコア

**bugfix-c で作成した合成音声の評価基盤を使ってください。**

正解テキストがあるので、WER（または文字誤り率）が測れるはずです。

- 日本語では **CER（文字誤り率）** のほうが適切かを判断してください
- スコアの定義を決める（例: `(1 - CER) × 100`）
- **算出方法を要件定義に明記すること**

**測定時間が倍になる点に注意してください。**
後述の測定モードで切り替えられるようにします。

### 表示

```
whisper.cpp / openvino_vulkan
  速度スコア: 780   （1時間の音声 → 約8分）
  精度スコア: 94    （CER 6%）

whisper.cpp / vulkan
  速度スコア: 880   （1時間の音声 → 約7分）
  精度スコア: 94

faster-whisper / cpu
  速度スコア: 200   （1時間の音声 → 約30分）
  精度スコア: 95
```

**「1時間の音声 → 約N分」という換算を併記してください。**
スコアだけでは実感が湧きません。

## 6a-3 — 測定モード

**全組み合わせの測定は数時間かかります。**段階を分けてください。

| モード | 内容 | 目安 |
|---|---|---|
| **簡易** | 短い音声、利用可能な構成のみ、**速度のみ** | 10〜20分 |
| **標準** | 中程度の音声、上位構成、速度＋精度 | 30〜60分 |
| **詳細** | 複数長・複数モデル、速度＋精度 | 数時間 |

- 各モードの具体的な内容（音声長、繰り返し回数、対象構成）を決めてください
- **所要時間の目安を、実行前に表示すること**
- 途中でキャンセルできること
- **中断しても、それまでの結果が失われないこと**

### 測定素材

| 用途 | 素材 |
|---|---|
| 速度 | **合成音声で十分**（内容に依存しないため） |
| 精度（日本語） | **合成音声**（正解が厳密） |
| 精度（実音声） | 後述 |

**合成音声はリポジトリに含め、測定の再現性を確保してください。**
bugfix-c のフィクスチャが流用できるはずです。

**実データを既定の測定素材にしないでください。**

### 実音声での精度測定（任意）

英語の実会議データ（AMI Meeting Corpus など）を使える形にするかを
**判断してください。**

- 使う場合、**取得は利用者に任せる**（ライセンスとサイズの問題）
- 使わない場合、合成音声のみである旨を明記する
- **無理に実装しなくてよい**
