## 最重要の制約

### 機密データの取り扱い

**`input/` の MP4 は実際の社内会議の録音です。**

- 文字起こし結果、話者名、音声由来のテキストを、`AISTATE.md`、`変更履歴.md`、
  試験報告書、コミットメッセージ、テストコード、コンソールの長文出力に**一切含めない**
- `input/` と `output/` の中身を git の追跡対象にしない
- assertion は内容ではなく、統計量・構造・書式に対して行う
- 元の MP4 を変更・削除・移動しない（読み取りのみ）
- **各コミットの直前に、実データが混入していないことを確認する**

### 秘密情報

- `.env` に `HF_TOKEN` が設定されています。**読み取って表示しない、編集しない、
  コミットしない。**
- トークン未設定時の挙動を試験する際も `.env` を編集せず、
  環境変数の上書きか隔離した作業ディレクトリで行う

### git の運用

- 作業ブランチ `test/acceptance-phase3` を新規作成する
- 開始時のコミットハッシュを記録する
- **試験グループが1つ終わるごとにコミットする**
- 不具合修正は試験実行とは別のコミットに分ける
- `git push` を実行しない
- 未コミットの作業を破棄する操作（`reset --hard`、`checkout -- .`、`clean -fd`）を行わない
- 履歴を書き換えない

接頭辞: `test:` / `fix:` / `docs:` / `chore:`

## 合否判定の基準

### ASR 出力の妥当性（Phase 1/2 の基準を踏襲）

| 項目 | 合格条件 |
|---|---|
| 言語判定 | `ja` |
| タイムスタンプ | 単調増加、`start < end`、音声長を超えない |
| 単語タイムスタンプ | **所属セグメントの範囲内に収まる** |
| 空セグメント | 全体の 10% 未満 |
| 日本語文字比 | 50% 以上 |
| ハルシネーション | 同一テキストが 5 回以上連続しない |

### 話者分離出力の妥当性

| 項目 | 合格条件 |
|---|---|
| 話者数（自動） | 1 以上 20 以下 |
| 話者数（指定時） | 指定どおり |
| 平均ターン長 | 0.5 秒以上 |
| `UNKNOWN` の割合 | 20% 未満 |
| 分布 | 1話者が全体の 99% を超えない |

### Phase 3 固有の基準

**構成間の一致度**（同一音声を複数構成で処理した場合）

浮動小数の演算差により完全一致は期待できません。以下を基準とします。

| 項目 | 合格条件 |
|---|---|
| セグメント数 | 構成間の差が ±20% 以内 |
| 単語数 | 構成間の差が ±25% 以内 |
| 総文字数 | 構成間の差が ±15% 以内 |
| 話者数 | **完全一致** |

話者数が構成によって変わる場合は不具合として扱ってください。

**CPU / XPU の話者分離一致**

| 項目 | 合格条件 |
|---|---|
| 話者数 | 完全一致 |
| 話者区間の数 | 完全一致、または ±1 |
| 各区間の境界時刻 | 差が 0.1 秒以内 |

Phase 3c では 1 話者音声で完全一致していました。複数話者でも同等の一致が
得られることを確認します。一致しない場合、**即座に不具合と断定せず**、
差の大きさを記録したうえで「要確認」とし、原因を調査してください。

## 試験項目

グループ単位で実施し、各グループ終了時にコミットしてください。

### P0. 疎通確認

1. 現在のプロファイルで `clip_30s` を `--no-diarization` で処理し、5形式を出力
2. 終了コード 0、出力5ファイル、JSON 構造が妥当

**ここで失敗したら以降に進まず、原因を調査・修正してください。**

### P1. プロファイル管理

1. `setup.ps1 -List` が作成済みプロファイルを表示する
2. `cpu` プロファイルの作成または更新が成功する
3. `intel` プロファイルの作成または更新が成功する
4. `vulkan` プロファイルの作成または更新が成功する
5. **あるプロファイルの更新が、他のプロファイルに影響しない**
   （更新前後で他プロファイルの torch のバージョンとビルド種別が変わらないこと）
6. `setup.ps1 -SetDefault <profile>` が既定を変更する
7. `setup.ps1 -Remove <profile>` が対象と解放容量を表示し、確認を求める
   （実際の削除は、再作成の時間を考慮して1つだけ試す。復元すること）
8. 旧 `.venv` / `.venv-windows` が残っている場合、移行案内が表示される
9. 各プロファイルの venv サイズを実測し記録する

**`cuda` プロファイルは作成しないこと。**

### P2. 実行手段

1. `run.ps1 transcribe ...` が既定プロファイルで動作する
2. `run.ps1 -Profile intel transcribe ...` が明示指定で動作する
3. 存在しないプロファイルの指定が、`setup.ps1` の案内付きでエラーになる
4. どのプロファイルで実行しているかが起動時に表示される
5. 終了コードが透過される（意図的に失敗させて確認）
6. `utteran profiles list` / `current` / `path`

### P3. ネイティブビルド

1. `utteran native status` が manifest の内容を表示する
2. 4構成すべてが利用可能と表示される
3. `utteran native build` の再実行が、ビルド済み構成をスキップする
4. `utteran native build --variant cpu --force` が対象のみ再ビルドする
5. manifest に OpenVINO の絶対パスが焼き込まれていない
6. manifest の whisper.cpp コミットハッシュが記録どおり（v1.9.1）
7. **`vulkan` プロファイルからも、同じビルド成果物が使えること**
   （ビルド成果物がプロファイル間で共有される設計の確認）
8. `utteran native clean --variant <名前>` の後、再ビルドで復旧する

ビルドには時間がかかります。タイムアウトを十分に取ってください（構成ごとに30分以上）。

### P4. モデルカタログ

1. `models list` / `models list --available` / `--all` の表示
2. `models list --json` の構造が妥当
3. ggml モデルが量子化違いを含めて登録されている
4. `.en` 系が既定一覧に出ず、`--all` でのみ出る
5. 小容量モデル（`base` など）の取得 → `verify` → 削除 → 再取得
   （**large 系の導入済みモデルは削除しないこと**）
6. 曖昧な ID 指定が候補提示付きで拒否される
7. 未登録 ID がエラーになる
8. 非対話環境での ID 省略が拒否される
9. `models path` が保存先を表示する

### P5. OpenVINO IR 変換

1. `models list-openvino` が変換済み IR を表示する
2. 未変換のモデルに対する `prepare-openvino` が、
   PyTorch 重みの追加ダウンロードを事前に告知し確認を求める
3. **小容量モデル（`base` など）で変換を実行し、成功する**
   （large 系は既に変換済みのため、時間節約のため小容量で試す）
4. `--purge-cache` が PyTorch 重みのキャッシュを削除する
5. 量子化違いのモデルから、同一サイズの IR が参照できる（規約名リンクまたはコピー）
6. `models verify` が IR の存在と整合性を検証する
7. `models remove-openvino` が動作する
8. **cp932 問題の回帰確認**: 変換処理の標準出力に非 ASCII 記号が含まれても失敗しない
   （Phase 3b で修正済み。UTF-8 固定が維持されているか）
9. `[openvino]` extras のないプロファイル（`cpu`）で `prepare-openvino` を実行した際、
   必要な extras を案内するエラーが出る

### P6. whisper-cpp ASR（4構成）

`clip_03m` を使用します。**`cpu` 構成は非常に遅い**（180秒音声に約463秒）ため、
`clip_30s` で確認してください。

1. `--asr-device cpu`（whisper-cpp）で完走する ※ clip_30s
2. `--asr-device openvino` で完走する
3. `--asr-device vulkan` で完走する
4. `--asr-device openvino_vulkan` で完走する
5. 4構成の出力が「構成間の一致度」の基準を満たす
6. **日本語ユーザー名パスの回帰確認**: 既定のモデル保存先で全構成が完走する
   （Phase 3b で 0xC0000409 が発生した条件。ASCII-safe な一時リンクの仕組みが機能しているか）
7. 量子化モデル（q5_0）＋ OpenVINO IR の組み合わせが動作する
8. 存在しない構成名の指定がエラーになる
9. ネイティブビルド未実施の構成を指定した際、`native build` を案内するエラーが出る

### P7. 単語レベルタイムスタンプ

1. `word_timestamps = auto` で、話者分離ありのとき単語が取得される
2. `word_timestamps = auto` で、`--no-diarization` のとき単語が取得されない
3. `word_timestamps = always` で、話者分離なしでも単語が取得される
4. `word_timestamps = never` で単語が空になる
5. **単語時刻がすべてセグメント範囲内に収まる**
6. `t_dtw` が全トークンで `-1` の場合に警告が出て、単語が破棄される
   （DTW を無効化した状態を人工的に作って確認する）
7. **日本語のトークン結合が正しい**：出力テキストに文字化け（`\ufffd` など）がない
8. faster-whisper と whisper-cpp の単語数を比較し、差を記録する
   （Phase 3b では +18%。`align.py` の閾値への影響を再確認）

### P8. auto 選択とフォールバック

1. `utteran devices` の末尾が、auto の選択結果と理由を表示する
2. Intel 環境で ASR の auto が `openvino_vulkan` を選ぶ
3. 話者分離の auto が `xpu:0` を選ぶ
4. auto での実行が完走する
5. GPU 初期化失敗時のフォールバックが動作する
   （環境変数などで人工的に失敗させられるなら試す。できない場合は「未実施」と記録）
6. **明示指定時はフォールバックせずエラーになる**
7. `--asr-device cuda` が、NVIDIA 不在の環境で分かりやすいエラーになる

### P9. XPU 話者分離

1. `--diarization-device xpu` で完走する
2. `--diarization-device cpu` で完走する
3. **`clip_03m_multi`（複数話者）で CPU と XPU の結果が
   「CPU / XPU の話者分離一致」の基準を満たす**
4. XPU での同一条件2回実行が一致する
5. `--num-speakers` 指定が XPU でも効く
6. `cpu` プロファイルで `--diarization-device xpu` を指定した際、
   プロファイル不整合と分かるエラーが出る
7. XPU のメモリ不足時のエラーが、共有 RAM の説明を含む理解可能な内容である
   （人工的に発生させられない場合は「未実施」と記録）
8. `--asr-device openvino_vulkan --diarization-device auto` の組み合わせが動作する
   （Phase 3c follow-up で修正された経路の回帰確認）
9. `--device` のみを指定した従来形式が、互換動作する

### P10. 結合検証

**Phase 3b / 3c で保留になっていた項目です。**

`clip_03m_multi` に対して以下を実行し、比較してください。

| ID | ASR | 話者分離 |
|---|---|---|
| A | faster-whisper / cpu | pyannote / cpu |
| B | whisper-cpp / openvino_vulkan | pyannote / cpu |
| C | whisper-cpp / openvino_vulkan | pyannote / xpu |

比較指標:

- 検出された話者数
- 話者ごとの発話時間の分布
- 平均ターン長
- `UNKNOWN` の割合
- セグメント数、単語数

**目的は「whisper-cpp 経由の話者割当が faster-whisper 経由と同等の妥当性を持つか」の確認です。**

差が出た場合、`align.py` の閾値をバックエンド別に調整する必要があるかを判断し、
判断と理由を記録してください。調整する場合は要件定義も更新すること。

### P14. 長時間耐久

`input/` の実ファイル（約2時間20分）を、**Intel 環境の最速構成**で処理します。

```
ASR: whisper-cpp / openvino_vulkan
話者分離: pyannote / xpu
```

1. 話者分離なしで処理し、所要時間・ピーク RAM を記録
2. 話者分離ありで処理し、所要時間・ステージ別内訳・ピーク RAM を記録
3. 出力の妥当性を「合否判定の基準」で検証
4. 同一条件の再実行が全ステージをスキップする
5. 実時間比を算出する

参考: CUDA 機（GTX 1070 Ti）では 2時間19分を話者分離込み 770.6秒（実時間比 10.85倍）でした。
Intel 機の数値と比較できるようにしてください。

**Arc 140T は共有メモリ構成のため、RAM 消費に注意してください。**
メモリ不足で失敗した場合、それ自体は既知課題（要件定義13章）として記録し、
不具合とはしません。ただし**エラーメッセージが不親切なら修正対象**です。

タイムアウトは最低4時間。30分以上ログが更新されない場合はハングとして中断・記録。

### P15. 文書整合性と AISTATE の整理

1. README の全コマンド例を実行し、動作すること
2. README のオプション一覧と `--help` が一致すること
3. README の性能表に Intel 機の数値が反映されていること
4. 要件定義に記載された設定項目が実装に存在すること
5. 終了コード表が実装と一致すること
6. **`AISTATE.md` の「未解決の課題・保留事項」を整理する**
   - Phase 3c Step 0 で解消した項目（pyannote XPU E2E、トークン不在）を削除する
   - 本試験で解消した項目を削除する
   - `cuda` プロファイル未検証は、ハードウェア不在の制約として残す
   - 現在地が一目で分かる状態にする

### P16. 事後処理

1. 全試験結果の集計
2. 削除したプロファイルの復元
3. `output/_testdata/` の整理（結果は残す）
4. 2時間ファイルのジョブは削除しない
5. 最終プロファイルの状態を記録
6. 報告書の作成と最終コミット

## 不具合を発見した場合

### 手順

1. 再現する最小手順を特定する
2. 原因を調査する
3. **修正前に、失敗結果をコミットする**（`test:`）
4. 修正を実装する
5. **回帰テストを追加する**（モデル不要でテストできる形にすること）
6. `ruff check`、`mypy`、`pytest -m "not requires_model"` を通す
7. 該当文書を更新する
8. `fix:` でコミットする
9. 失敗した試験を再実行し、合格を確認する

### 修正すべきでない場合

以下は修正せず記録のみとしてください。

- Phase 4 以降の未実装機能に起因するもの
- 仕様変更を伴い、利用者の判断が必要なもの
- 実音声の性質による可能性があり、不具合と断定できないもの
- 修正の影響範囲が大きく、他の試験結果を無効化するもの
- **NVIDIA ハードウェアがないと検証できないもの**

判断に迷う場合は**修正しない**を選び、記録してください。

### 優先順位

1. データ損失、秘密漏洩につながるもの
2. 正常系が動作しないもの
3. 環境分離による既存機能の回帰（P11 で発見されたもの）
4. エラー処理が不適切なもの
5. 文書と実装の不一致
6. 表示上の軽微な問題

## 時間配分の目安

Intel 環境の ASR は高速（`openvino_vulkan` で実時間比 5倍以上）なので、
CUDA 機での試験より短時間で終わる見込みです。

| 区分 | 目安 |
|---|---|
| 準備、素材生成、ハーネス拡張 | 40分 |
| P1〜P5（環境・ビルド・モデル） | 1.5〜3時間（ビルド時間に依存） |
| P6〜P13（機能・性能） | 2〜3時間 |
| 不具合修正 | 随時 |
| P14（耐久） | 1〜2時間 |
| P15〜P16（文書・報告） | 40分 |

**P13 までを終える前に P14 を始めないでください。**
不具合を含んだコードで長時間処理を回すと時間が無駄になります。

時間が足りない場合、P14 の「話者分離あり」を優先し、
`cpu` 構成の whisper-cpp 試験（P6-1）を省略してください。

利用者は確認できません。以下の方針で進めてください。
