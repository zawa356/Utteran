## 背景

### 解決したい問題

**Smart App Control が有効な環境で、`utteran-gui.exe` の起動が阻止されます。**

実測で確認済みです。**インストール自体は完了しますが、起動できません。**
ポータブル版（ac-4）も同じ exe を使うため、同じ環境では同様に阻止されます。

E グループで SignPath Foundation による署名を取得する予定ですが、
**審査には時間がかかり、それまで使えない環境が残ります。**

### 想定する回避の原理

**PyInstaller で凍結した未署名の exe ではなく、
Python インタプリタを直接起動する経路を用意します。**

`uv` が構築した venv の `python.exe` は Python 公式ビルドのバイナリであり、
署名と評価の両面で既知のバイナリとして扱われるため、
**Smart App Control を通る可能性があります。**

### 重要 — 効果は未確認です

**この効果は検証されていません。**

利用者の手元に Smart App Control が有効な機がなく、
**本作業の時点では確認できません。**

以下の懸念が残っています。

- Smart App Control は**プロセス起動だけでなく DLL の読み込みも検査**する
- `torch`、`openvino`、`openvino-genai` などは**大量のネイティブ DLL** を含む
- **whisper.cpp のネイティブビルドは、利用者の機で cmake が生成したバイナリ**であり、
  署名も評価もない。**ここが最も阻止されやすい**

**したがって、Smart App Control 回避は「期待される効果」であり、
「確定した効果」ではありません。文書でもそう扱ってください。**

### それでも実装する理由

**Smart App Control とは無関係に価値があります。**

- ソースから使いたい利用者、既に Python 環境を持つ利用者に有用
- 開発者向けの手順を、利用者向けの経路として整備できる
- exe を信用しない環境、企業のポリシーで exe の実行が制限される環境にも対応できる

**目的を Smart App Control 回避に限定しないでください。**

## Step 1 — 起動経路の整備

### 現状

`setup.ps1` / `gui.ps1` / `run.ps1` / `start.ps1` が既にあり、
開発環境ではこの経路で動作しています。

**ゼロから作るのではなく、開発者向けの前提を利用者向けに埋める作業です。**

### 課題

**PowerShell の実行ポリシーが障壁になります。**

既定の Restricted では `.ps1` を実行できません。
利用者に実行ポリシーの変更を求めるのは、**セキュリティ機構の迂回を促すことになります。**

### 方針

**`.bat` から起動する経路を用意してください。**

- bat が PowerShell スクリプトを呼び出す
- 実行ポリシーの制約を回避する（**利用者に恒久的な設定変更をさせない**）
- **何をしているかを利用者へ説明する**（隠さない）

**恒久的に実行ポリシーを変更させないこと。**
その起動に限定した扱いにしてください。

### 前提条件の確認と案内

**この経路では、Python / uv / ffmpeg の導入が利用者の作業になります。**

- **起動時に前提条件を確認する**
- 不足しているものを**具体的に示す**（「環境が不正です」のような曖昧な表示にしない）
- 導入方法を案内する
- **自動で導入しない**（利用者の環境を勝手に変更しない）

### データの配置

**ac-4 で共通の resolver を実装済みです。それを使ってください。**

この経路でのデータ配置をどうするかは判断が必要です。

- インストーラー版と同じユーザー領域
- ポータブル版と同じ自ディレクトリ配下
- リポジトリの位置に依存する既存の挙動

**判断し、理由を記録してください。**
**ac-4 の resolver に新しい分岐を増やさない形が望ましい。**

### 注意

**インストーラー版とポータブル版の挙動を変えないでください。**

## Step 5 — `dist` の整理（独立したコミットにする）

### 現状の問題

`dist` に中間生成物と最終成果物が混在しています。

```
dist/
├─ utteran-portable-0.1.24.zip          ← 成果物
├─ utteran-portable-0.1.24.zip.sha256   ← 成果物
├─ installer/
│  ├─ utteran-setup-0.1.24.exe          ← 成果物
│  └─ utteran-setup-0.1.24.exe.sha256   ← 成果物
├─ portable-stage/                       ← 中間生成物
└─ utteran-gui/                          ← 中間生成物
```

**最終成果物が2階層に分かれ、中間生成物と同じ場所にあります。**

### 求める構成

- **最終成果物と sha256 を同一階層に揃える**
- **中間生成物を分離する**（別ディレクトリ、または明確に区別できる名前）
- どれを配布すればよいかが、**一目で分かる**こと

具体的な構成は判断に任せます。**なぜその構成にしたかを記録してください。**

### 注意

- **`.gitignore` の対象を確認する。**中間生成物がコミットされないこと
- **`build.ps1` の出力先変更が、他の処理に影響しないこと**
  （インストーラー定義、CI の想定、`reset-env.ps1` など）
- **E グループで SHA-256 の公開を扱う予定があります。**
  配置が安定していると後の作業が楽になります
