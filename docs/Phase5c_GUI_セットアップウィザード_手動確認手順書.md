# Phase 5c GUI セットアップウィザード 手動確認手順書

## 目的と安全上の注意

初回セットアップウィザード（ハードウェア検出、推奨profile提示、uv自動導入、venv構築、ffmpeg、
モデル取得、Hugging Faceトークン設定、実動作確認）をWindows native WebViewで確認する。
実tokenやAPI応答、実logを画面capture、報告、Gitへ転記しない。実動作確認には
`wave`標準ライブラリで生成した無音の合成WAVだけを使い、実録音・実tokenは使用しない。
既存の`.venvs`／`.env`／keyringエントリ／利用者の実jobを壊す操作は行わない。

## 事前準備

```powershell
.\setup.ps1 -Profile gui -Yes
.\gui.ps1
```

本機は既にuv・`intel`／`cpu`／`vulkan`profile・ffmpegを導入済みのため、「何もない状態からの
初回起動」はこの機では再現できない。以下の項目は**実機未検証**として扱い、代わりに
`tests/test_setup_wizard.py`・`tests/test_hardware.py`のfakeによる回帰と、AISTATE.mdに記録した
隔離環境（一時ディレクトリ）での実機部分検証で代替した。

- 真に空の`.venvs`からの初回起動フロー全体
- `cuda`profile（本機にNVIDIA GPUなし）
- uv未導入状態での`Install-Uv`のダウンロード分岐（本機は既にuv導入済みのため到達しない）
- ユーザーPATHへの永続書き込み分岐

## 1. 初回起動判定とウィザードの起動

1. GUI設定画面（「設定」）に「ウィザードを開く」ボタンがあり、いつでもウィザードを開ける。
2. `settings.json`が存在せず、かつプロファイルvenvが1つもない環境（隔離した検証用checkout等）
   では、GUI起動直後にウィザードが自動的に開くことを確認する。
3. 既にプロファイルvenvと`settings.json`を持つ環境（本機相当）では、GUI起動時にウィザードが
   自動的に開かないことを確認する（既存利用者を煩わせない設計）。
4. ウィザードの「後で行う」を押すと通常の文字起こし画面へ戻り、次回起動時に再度自動起動する
   （完了記録が保存されていないため）。

## 2. ハードウェア検出と推奨

1. 「始める」を押すとハードウェア検出が実行され、実際のGPU名（本機なら`Intel(R) Arc(TM) 140T
   GPU`のような実名）を含む推奨理由が表示される。
2. 推奨profileのカードに「おすすめ」表示があり、**文字起こしの高速化**と**話者分離のGPU実行**
   が別々に表示される（intelなら両方○、vulkanなら文字起こしのみ○で話者分離は×）。
3. 選択できるprofileが、実際にこの機で選べるものだけに絞られていることを確認する
   （本機にNVIDIA GPUがないため`cuda`のカードが出ない）。
4. カードのディスク使用量の目安が概算であることを確認する（実際のダウンロード量と大きく
   異なる場合は指示書のAISTATE記録を更新する）。

## 3. venv構築の進捗

1. 構成を選び「この構成で始める」を押すと進捗画面へ切り替わり、現在のステージ名
   （`python_check`/`uv_install`/`venv_sync`/`ffmpeg`/`env_setup`/`verify`のいずれか）が
   具体的に表示される（「準備中…」のような無内容な表示にならない）。
2. 詳細ログに`setup.ps1`の実際の出力行（パッケージ導入、既存ffmpeg検出等）が流れる。
3. しばらく進捗がない場合に「応答待ち」表示が出て、停止と誤認しないことを確認する。
4. 「キャンセル」を押すとプロセスツリーが終了し、エラー画面へ遷移する。既存の`.venvs`が
   壊れていないことを確認する。
5. 失敗した場合、エラー画面に具体的な案内（`guidance`）と「再試行」ボタンが表示される。

## 4. モデル取得とHugging Faceトークン

1. モデル選択画面で既定モデル（large-v3-turbo）が明示され、「話者分離も使う」を
   チェックしない場合はトークン画面を経由せずモデル取得へ進む。
2. 「話者分離も使う」をチェックすると、トークン画面へ遷移し、モデル利用条件ページへの
   リンクが開けることを確認する。
3. 有効なトークンを保存すると「設定済み」表示になり、**入力した値が画面に再表示されない**
   ことを確認する。保存先はOS keyring（`utteran`/`huggingface`）のみである。
4. 「話者分離なしで進める」を押すと、話者分離モデルを取得せずに実動作確認へ進む。
5. 無効なトークンでモデル取得を実行し、「トークンが無効です」という案内が出ることを確認する。
6. 有効なトークンだが利用条件に未同意の状態でモデル取得を実行し、「トークンは有効だが
   利用条件に同意が必要」という、上記4と異なる案内が出ることを確認する
   （`license`と`token`カテゴリの区別）。

## 5. 実動作確認（smoke test）と完了

1. 実動作確認は無音の合成音声で実行され、実際の音声ファイルを要求しない。
2. 成功すると完了画面が表示され、「準備が完了しました」ことだけでなく実際に動作確認できた
   旨が伝わる文言になっている（未確認のまま完了と表示しない）。
3. 「文字起こしを始める」を押すと通常の文字起こし画面へ遷移し、選んだprofileが反映されている。
4. 完了後、設定画面から再度ウィザードを開いても、GUI起動時には自動的には開かないことを
   確認する（`setup_wizard_completed_at`が保存されているため）。

## 自動確認へ委ねる項目

- ハードウェア検出→推奨profile算出の分岐網羅（NVIDIA/Intel/AMD/不明/GPUなし）
- venv構築・モデル取得・実動作確認ジョブの1操作制限、cancel、event cursor、`##UTTERAN-WIZARD##`
  マーカー行のパース
- `license`と`token`ガイダンスカテゴリの区別
- 初回起動判定（設定ファイル有無・プロファイルvenv有無）の分岐
- `setup_wizard_completed_at`の保存とsmoke_test成功前の完了拒否（409）
- `utteran_gui`配下に推論系依存（torch/openvino/ctranslate2/faster_whisper/pyannote）が
  importされていないことのAST回帰

これらは`tests/test_hardware.py`、`tests/test_setup_wizard.py`、`tests/test_gui.py`で回帰検査する。
