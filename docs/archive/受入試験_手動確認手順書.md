# 受入試験 手動確認手順書

この文書は、操作の性質上そもそも自動化できない Phase 3d 以来の恒久確認項目を扱う。
環境制約によって AI が実施できなかった作業ごとの項目は、ルートの
[`ユーザー確認事項.md`](../../ユーザー確認事項.md)を参照すること。

Phase 3d R-4（受入試験ハーネス統合）で、宣言的ケースへの自動移植が適さないと判断した項目を
ここに記録する。`tools/acceptance/cases.json` の全ケースには含まれないため、環境を変更した際は
このチェックリストを人手で再確認すること。

## この文書に載せる基準

`utteran_Phase3d_最終指示書.md` の分類方針に従い、以下のいずれかに該当するものだけを載せる。

- 対話メニューでの選択操作そのものが確認対象で、パイプ入力による疑似操作では
  「メニューが動くこと」以上を検証できない
- Explorerなど外部GUIアプリケーションの起動が確認対象
- 破壊的操作の確認プロンプト表示そのものが確認対象（内容は`command-output`で確認済み）

これ以外はすべて`tools/acceptance/cases.json`のケースとして自動化した。移植・自動化した項目の
一覧は`tools/acceptance/README.md`の分類表を参照。

## P12: `start.ps1` 対話メニュー

`G12-01`（`scenarios.py start-front`）がPowerShell Parser検証、コマンドマッピングの監査、
読み取り専用メニューのパイプ入力smoke test、文字起こしウィザードのdry-run smoke testまでを
自動実施する。同ケースの実行結果JSONは`manual_only`キーで以下を自己申告しており、
この文書はその3項目の具体的な確認手順を補う。

| 項目 | 自動化しなかった理由 |
|---|---|
| プロファイル管理メニューでの切替 | セッション内のプロファイル切替は対話選択の結果を人間が目視するための機能で、パイプ入力では選択後の表示更新を意味のある形で検証できない |
| input/outputフォルダをExplorerで開く | `explorer.exe`起動は外部GUIプロセスで、起動成功の判定に画面確認が必要 |
| 破壊的操作（プロファイル削除等）の確認プロンプト | プロンプト文言自体は`P1-7a`など`command-output`ベースのケースで確認済み。ここでの残りは「実際に対話中に`n`で中断できるか」という人間的操作の確認 |

### 手順

1. `.\start.ps1` を通常のコンソール（PowerShell、`ConPTY`ではなく実ウィンドウ）から起動する。
2. メインメニューから「プロファイル管理」を選び、一覧表示→セッション内切替→切替後の
   メインメニュー表示に現在のプロファイル名が反映されることを目視確認する。
3. メインメニューから入力/出力フォルダを開く操作を選び、Explorerウィンドウが実際に開き、
   対象フォルダ（`input/`または`output/`）が表示されることを確認する。
4. プロファイル削除など破壊的操作を選び、確認プロンプトで`n`を入力して中断できること、
   `y`を入力すると実際に処理が進むことを確認する（環境を変更するため、確認後は
   `setup.ps1 -Profile <name>`で復元すること）。
