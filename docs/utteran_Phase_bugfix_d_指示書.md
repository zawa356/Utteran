## D-1 — 発話が出力されていない（最優先）

### 事実

**発話が割り当てられていない10秒以上の空白が18箇所、合計約463秒。**
収録時間 1,484.8 秒の **31%** に相当します。

| 区間 | 長さ |
|---|---|
| 00:14:59 → 00:16:06 | 66.4秒 |
| 00:13:13 → 00:14:14 | 60.2秒 |
| 00:08:45 → 00:09:42 | 57.3秒 |
| 00:18:55 → 00:19:38 | 42.7秒 |
| 00:16:30 → 00:17:10 | 39.8秒 |
| 00:22:35 → 00:23:09 | 34.2秒 |
| 00:00:21 → 00:00:50 | 28.8秒 |
| （他11箇所、10〜15秒） | |

**評価者の指摘:**

> いずれも直前が問いかけで終わっており、その間の応答が欠落している疑いがあります。
> 話者分離の評価以前に、発言単位での網羅性に影響します。

**発言が出力されていないなら、議事録として成立しません。
話者分離の精度以前の問題です。**

### 疑うべき箇所

**推測で修正しないでください。**以下を順に確認してください。

| 仮説 | 確認方法 |
|---|---|
| A. **bugfix-c の「異常に長い単語を含む ASR 区間の除外」が過剰** | 除外されたセグメント数と時間を記録。除外を無効化して比較 |
| B. VAD が発話区間を除去している | VAD の有無で比較。VAD が検出した speech 区間と突き合わせる |
| C. ASR がそもそも出力していない | ASR 段階（`asr.json`）で既に欠落しているかを確認 |
| D. 話者割当で捨てられている | `merged.json` と `asr.json` を比較 |
| E. 実際に無音である | 該当区間の音声レベルを測定 |

**A が最有力です。**bugfix-c で追加した除外処理が、
**正常な発話まで巻き込んでいる**可能性があります。

### 切り分けの手順

**段階ごとに何が残っているかを比較してください。**

```
音声（1,484.8秒）
  ↓
[1] VAD が検出した speech 区間の合計
  ↓
[2] asr.json のセグメントの合計時間
  ↓
[3] 除外処理の後
  ↓
[4] merged.json のセグメントの合計時間（実測: 956.1秒）
```

**どの段階で 463秒が失われたかを特定してください。**

0.1.11 で追加した段階統計ツールが使えるはずです。
使えない場合、比較する手段を作ってください。

### 該当区間の音声を確認する

**実際に無音なのかを確認してください。**

- 該当区間（例: 00:13:13 → 00:14:14）の音声レベルを測定する
- **無音なら問題なし**（会議中の沈黙、資料確認など）
- **発話があるのに出力されていないなら不具合**

`ffmpeg` の `volumedetect` や `astats` フィルタで測定できます。
**音声を聞く必要はありません。**レベルの数値で判定してください。

### 対処

**除外処理が原因だった場合:**

- 除外の条件を見直す
- **何を除外したかを必ずログに記録する**（現在は黙って捨てている可能性）
- 除外した区間の合計時間を、処理完了時に表示する
- 除外率が高い場合、警告を出す

**bugfix-c の意図（異常な時刻を持つ区間を排除する）は維持しつつ、
正常な発話を巻き込まないようにしてください。**

## D-2 — UNKNOWN の生成条件

### 事実

**UNKNOWN が15区間。うち15区間すべてが発話の途中に挟まっています。**

| 位置の性質 | 区間数 |
|---|---|
| 語内 | 6 |
| 文末助詞のみ | 6 |
| 名詞＋敬称の分断 | 1 |
| 主語相当の分断 | 1 |
| 相槌 | 1 |

- 時間占有率は **0.53%**（5.04秒 / 発話総計 956.1秒）
- 10区間が 0.5秒未満、うち **5区間が 0.03秒以下**
- **0.01秒に3文字が入っている区間**が存在（00:21:49.64）

**評価者の判定:**

> 文脈的に本当に判別困難な区間は 0件。
> 音響的判定が成立する長さではありません。

### 語内分断との関係

**これが本作業で最も重要な発見です。**

語内で3話者にまたがる分断が7箇所ありますが、**そのうち5箇所は中間が UNKNOWN です。**

| 時刻 | 遷移 | 中間長 |
|---|---|---|
| 00:02:30.28 | 00 → **UNKNOWN** → 02 | 0.10秒 |
| 00:03:30.56 | 00 → **UNKNOWN** → 00 | 0.83秒 |
| 00:04:00.16 | 00 → **UNKNOWN** → 02 | 1.55秒 |
| 00:05:42.52 | 02 → **UNKNOWN** → 00 | 0.04秒 |
| 00:11:26.70 | 00 → **UNKNOWN** → 02 | 0.08秒 |

**bugfix-c で導入した Viterbi が、UNKNOWN を対象外にしている疑いがあります。**

話者間の遷移にはペナルティがかかるが、**UNKNOWN への遷移にはかからない**構造なら、
この結果になります。

### 実施内容

1. **Viterbi の実装を確認し、UNKNOWN の扱いを調べる**
   - 状態として含まれているか
   - 遷移ペナルティの対象か
   - 対象外なら、なぜそうしたかを確認する
2. **UNKNOWN を Viterbi の状態として扱う**
   - 話者と同様に遷移ペナルティをかける
   - `A → UNKNOWN → A` のような短い挿入が抑制されるようにする
3. **UNKNOWN の最小継続長を設ける**
   - 0.03秒の UNKNOWN は音響的に意味を持ちません
   - 最小長と最小文字数の下限を設定可能にする
   - **既定値の根拠を実測で示すこと**

**時間占有率が 0.53% しかないため、除去による情報損失はほぼありません。**

## D-3 — 語内分断の後処理

### 事実

**語内分断が16箇所（境界数23）。うち7箇所は3話者にまたがります。**

**分断点の位置に明確な傾向があります。**

> 分断点は語頭1文字目の直後に集中しており、16箇所中13箇所（81%）がこの形です。
> （語の1文字目だけが前話者ラベルに残る）

区間長は 0.01〜2.62秒に広がっており、**単純な秒数閾値では捉えきれません。**

### 評価者の提案

> 「1〜2文字かつ0.5秒未満のセグメントは、時刻の近い側ではなく
> 前後どちらか長い側のラベルへ吸収する」ルールで大半が消えます。
> 効果が最も大きく、実装コストが最も小さい部分です。

### 実施内容

**D-2 の修正で解消する分を除いた上で、残る分断に対処してください。**

- 短いセグメントを、**時刻の近さではなく前後の長さで判断して吸収する**
- 語頭1文字だけが取り残されるパターンを検出する
- **短い相槌を消さないこと**（後述）

**Viterbi のペナルティ調整で解決するなら、そちらを優先してください。**
後処理を重ねるより、系列最適化の中で扱うほうが一貫します。

### 事実

さらに、**00:17:10 から 105.26秒の単一セグメント**が存在します。

- 105秒の単一セグメントが生まれる条件を調査する

## 短い相槌を消さないこと

**すべての修正で、この制約を守ってください。**

現状では以下が確認されています。

- 独立して保持されている短い相槌: **4箇所**（最短 0.07秒）
- **前後の話者に吸収された疑いのある相槌: 8箇所**

> 「短い相槌が独立セグメントとして立っている場合は残るが、
> 長尺セグメントの端に接している相槌は吸収される」という非対称があります。

**平滑化を強めると、この8箇所がさらに増えます。**

bugfix-c で作成した合成音声の評価基盤に、**短い相槌の保持を検証するケース**が
含まれているはずです。無ければ追加してください。

## 実装上の注意

### 破壊的変更への配慮

- 既存の venv、モデル、設定、ジョブを壊さない
- **アルゴリズムの変更により、既存ジョブの `config_hash` が変わります**
- bugfix-c の成果（トークン境界の尊重、クラスタ数の安定）を壊さない
- Phase 5a〜bugfix-c の機能を壊さない

### 機密データ

- 実データの文字起こし内容を記録しない
- 音声レベルの測定結果は数値のみを記録する
- `.env` を読み取らない

### コミット

- ブランチ `fix/phase-bugfix-d-missing-speech`
- 段階ごとにコミットする
- `git push` は実行しない
- 実データ、ビルド成果物をコミットしない
