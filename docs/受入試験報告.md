  処理・構造・品質統計は合格したため製品不具合とは判定しなかった。
- Windows WDDMでは安全な汎用手段でper-process VRAMを得られないため、GPU全体のbaseline／peak／deltaを
  0.2秒間隔で測定した。表のVRAMは他processの影響を含む。
- WSLからWindows PowerShellを非対話起動した最初のCUDA setupは、WSL由来の不正な`PATHEXT`を
  継承してuv/Pythonを見失った。標準Windows `PATHEXT`で再実行すると成功し、通常のPowerShell利用では
  再現しない試験環境要因と判断した。

## 未実施・保留の試験と理由

- G6の「小容量モデルを削除→再取得→再削除」は、登録カタログに小容量モデルがないため条件不成立。
  導入済み大容量モデルを受入目的だけで削除する破壊的操作は行わなかった。一覧、取得エラー、verify、
  path、非対話案内は実施済み。
- G12のExplorer起動、setup profile切替、モデル／ジョブの実削除確認は外部UI・破壊的操作のため、
  Parser、32 command mapping、read-onlyメニュー、dry-run、確認処理のコード監査までとした。
- `.env`の値比較は指示書の禁止事項に従い未実施。内容を読まず、ignore確認と、生成物・例外・ログへ
  token形式値がないことを検証した。
- 約2時間19分ファイルのCPU処理は、G13でCUDAが成功したため実施しなかった。指示書ではCUDA失敗時の
  代替確認であり、CPU実行は推定で長時間となる。
- 実文字起こし本文の意味的な目視評価は機密保持のため自動では行わず、構造・統計検証に限定した。
