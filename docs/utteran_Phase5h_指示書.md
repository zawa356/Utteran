## H-1 — ASR が CPU 実行されている（最優先）

### 事実

Intel Arc 140T 搭載機での実測です。

```
large-v3-turbo · cpu
```

| フェーズ | 所要時間 |
|---|---|
| 音声抽出 | 00:00:03 |
| **文字起こし (ASR)** | **00:26:29** |
| 話者分離 | 00:14:56 |
| 合計 | 00:41:32 |

約1時間の音声に対し ASR で26分、**実時間比は約2.3倍**です。

Phase 3d の同一機での実測と比較します。

| 構成 | 実時間比 |
|---|---|
| whisper.cpp / Vulkan | 8.8倍 |
| whisper.cpp / OpenVINO+Vulkan | 5.5倍 |
| **faster-whisper / CPU** | **約2倍** |

**測定値が faster-whisper CPU の水準と一致しています。**
話者分離は GPU 使用率が100%に達しており、XPU で正しく動作しています。

**本来の約4倍の時間をかけています。**1時間の音声なら、26分が7分程度になるはずです。

### 調査すべきこと

**推測で修正しないでください。**なぜ CPU が選ばれたのかを特定してください。

| 仮説 | 確認方法 |
|---|---|
| A. GUI が `--asr-backend faster-whisper` を明示的に渡している | GUI が組み立てる CLI 引数を確認 |
| B. whisper.cpp のネイティブビルドが未実施 | `utteran native status` |
| C. ggml モデルが未取得 | `utteran models list` |
| D. auto 選択が faster-whisper へ退避している | `utteran devices` の auto 表示と理由 |
| E. GUI のデバイス選択肢に Vulkan などが出ていない | GUI の選択肢生成を確認 |

**特に E に注意してください。**Phase 5a で「選択肢は検出結果から動的生成する」と定めましたが、
whisper.cpp の構成（cpu / openvino / vulkan / openvino_vulkan）が
GUI の選択肢に含まれているかを確認してください。

### 対処方針

原因にかかわらず、**以下を満たすようにしてください。**

1. **GUI の既定が、その環境で最速の構成になる**
   - `utteran devices --json` の auto 選択結果を尊重する
   - GUI が独自に `faster-whisper` を既定にしない
2. **whisper.cpp の構成が GUI から選択できる**
   - ネイティブビルド済みで、ggml モデルがある場合に選択肢へ出る
3. **前提が揃っていない場合、それが分かる**
   - ネイティブビルド未実施なら、実行方法を案内する
   - ggml モデル未取得なら、取得方法を案内する
   - **「速い構成が使えるのに使っていない」状態を、利用者に気づかせる**
4. **実行結果に、使用した構成が明示される**（Phase 5b で実装済み）

### 検証

**同一の音声で、修正前後の ASR 所要時間を比較してください。**

- 実データを使う場合、**文字起こしの内容を記録しないこと**
- 所要時間、実時間比、使用した構成のみを記録する
- 短いクリップ（5〜10分）で構いません

**実時間比が5倍以上になることを確認してください。**
ならない場合、原因が残っています。

## H-5 — コンソールウィンドウの抑止

GUI の利用中、コンソールウィンドウ（黒い窓）が一瞬表示されます。

### 原因

`src/utteran_gui/processes.py` の 36 行目付近:

```python
if os.name == "nt":
    kwargs["creationflags"] = getattr(subprocess, "CREATE_NEW_PROCESS_GROUP", 0)
```

**`CREATE_NO_WINDOW` が指定されていません。**

GUI の exe は `console=False` でビルドされているためコンソールを持ちません。
この状態からコンソールアプリを起動すると、Windows が新しいコンソールウィンドウを
割り当てます。

### 対処

```python
if os.name == "nt":
    kwargs["creationflags"] = (
        getattr(subprocess, "CREATE_NEW_PROCESS_GROUP", 0)
        | getattr(subprocess, "CREATE_NO_WINDOW", 0)
    )
```

`getattr` で取得するのは、非 Windows での型チェックを通すためです。

### 対象箇所

| ファイル | 用途 |
|---|---|
| `src/utteran_gui/processes.py:36` | ウィザードとジョブの CLI 起動 |
| `src/utteran_gui/processes.py:47` | `taskkill` |
| `src/utteran_gui/cli.py:119` | |
| `src/utteran_gui/hardware.py:253` | PowerShell（`Get-CimInstance`） |
| `src/utteran_gui/api.py:457` | |

**`src/utteran_gui` 全体を検索し、漏れがないか確認してください。**
共通ヘルパーに集約できるならそうしてください。

### 必ず確認すること

**Phase 2 の受入試験で、Windows における Ctrl+C の伝播に関する不具合（U-002）を
解決した経緯があります。**`CREATE_NEW_PROCESS_GROUP` はその対処に関係している
可能性があります。

- GUI からのキャンセルでプロセスツリーが確実に終了する
- CLI 単体での Ctrl+C が従来どおり動作する（終了コード 130）
- 受入試験ハーネスの該当ケースが合格する
