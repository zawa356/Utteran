## 背景と位置づけ

### なぜ実装するのか

Phase 3 の設計時、Intel 環境の ASR として OpenVINO GenAI を候補に挙げましたが、
参考実装のベンチマークで OpenVINO 単体が Vulkan より遅いという結果を得たため、
**whisper.cpp + OpenVINO エンコーダ IR を採用しました。**

その後、`backend="openvino"` のカタログエントリだけが残り、
**推論が実装されていないのに GUI が選択肢として提示する**状態になっていたため、
Phase 5i で除去しています。

**本作業で、バックエンドとして正式に実装します。**

### 目的

**性能で勝つことは目的ではありません。**

- 将来 OpenVINO GenAI が改善される可能性がある
- 環境によっては有利かもしれない
- **バックエンドの選択肢として持つこと自体に価値がある**

**実測で不利と分かれば、推奨構成から外すだけです。**
実装したことは無駄になりません。

### 超えるべき水準

Intel 機（Core Ultra 7 255H + Arc 140T）での Phase 6a 実測です。

| 構成 | 180秒 | 900秒 | 3600秒 | 10363秒 |
|---|---:|---:|---:|---:|
| **whisper.cpp / openvino_vulkan** | 827 | 1733 | 1777 | **1700** |
| whisper.cpp / vulkan | **1149** | 1594 | 1451 | 1358 |
| whisper.cpp / openvino | 624 | 988 | 982 | 945 |

**長時間では ovvk が 1700。**これが比較対象です。

## Step 0 — 事前調査（最優先・ここで打ち切り可能）

**実装の前に、以下を確認してください。**

### 調査項目

**I-1. 単語レベルタイムスタンプの取得可否（最重要）**

utteran は `align.py` で**単語の中心時刻**を使って話者を割り当てます。
**単語タイムスタンプが取れないバックエンドは、話者分離に使えません。**

- OpenVINO GenAI の `WhisperPipeline` で、単語単位の時刻が取得できるか
- 取得できる場合、その形式と精度
- **CPU / GPU / NPU のどれで取得できるか**（デバイスによって差がある可能性）
- 取得に特別な設定（`return_timestamps` 等）が必要か

**Phase 3a の調査記録に「2026年の版で CPU/GPU/NPU すべてに対応した」という
情報がありますが、伝聞です。必ず実機で確認してください。**

**I-2. モデル形式と入手**

- 必要なモデル形式（OpenVINO IR）
- Hugging Face 等から取得できるか、変換が必要か
- **large-v3-turbo の IR が公開されているか**
- サイズ
- ライセンス

**I-3. デバイス指定**

- `CPU` / `GPU` / `NPU` の指定方法
- **NPU で動くか**（Core Ultra には NPU がある）
- NPU 使用時の制約（`STATIC_PIPELINE` の要否など）

**I-4. 最小実装での速度測定**

**本格実装の前に、速度の目安を得てください。**

- 数十行程度の最小コードで、短い音声を処理する
- **実時間比を測る**
- ovvk（1700）と比較して、桁違いに遅くないかを確認する

**I-5. 依存の追加**

- 必要なパッケージとサイズ
- 既存の `openvino` パッケージで足りるか、`openvino-genai` が別途必要か
- **torch との衝突がないか**（`intel` プロファイルは XPU 版 torch を使用）

### 判定

調査結果を以下に分類し、**`AISTATE.md` に記録してください。**

| 判定 | 条件 | 対応 |
|---|---|---|
| **A** | 単語タイムスタンプが取れ、速度も実用的 | Step 1 以降を実装 |
| **B** | 単語タイムスタンプが取れるが、速度が劣る | **実装する。**推奨から外すだけ |
| **C** | **単語タイムスタンプが取れない** | 後述の扱いに従う |
| **D** | 動作しない、依存が解決できない | **実装せず、理由を記録して終了** |

### 判定 C の扱い

**単語タイムスタンプが取れない場合でも、実装する価値はあります。**

- 話者分離を使わない用途（字幕生成など）では利用可能
- 将来対応する可能性がある

ただし、**以下を必ず実装してください。**

- 話者分離と組み合わせた場合、**単語なしで動作すること**
  （`align.py` のセグメント単位フォールバック経路）
- **その旨を利用者に警告すること**
  （「このバックエンドでは話者割当の精度が落ちます」）
- **auto で選ばれないこと**

**判定 C なら、実装するかを利用者に確認してから進めてください。**

### 判定 D の扱い

**無理に進めないでください。**

- 何が障害だったかを詳細に記録する
- 将来再検討する条件を記録する
- **バージョンが上がれば解決する可能性がある**旨も含める

## Step 1 — バックエンドの実装

### `ASRBackend` の実装

`src/utteran/asr/openvino_genai.py` を作成してください。

既存の `whisper_cpp.py` と `faster_whisper.py` が実装例です。

| メソッド | 実装内容 |
|---|---|
| `is_available()` | 必要なパッケージが導入済みか。**import 失敗を握りつぶして False** |
| `available_devices()` | OpenVINO の利用可能デバイス（CPU / GPU / NPU） |
| `load()` | モデルとデバイスの解決、パイプラインの初期化 |
| `transcribe()` | 認識の実行、**共通型への変換** |
| `unload()` | 解放 |

### 守るべき原則

**Phase 1 以来の設計です。**

- **バックエンド固有の型を上位層に漏らさない**
  戻り値は `TranscriptionResult`（`Segment` / `Word`）に統一する
- **進捗コールバックとキャンセルトークンを実装する**
- **明示指定時はフォールバックしない**（`auto` のときのみ退避）
- **モデルの暗黙ダウンロードを行わない**

### レジストリへの登録

`src/utteran/asr/registry.py` に登録します。

**Phase 5j で発覚した問題に注意してください。**
`registry.py` が `allow_fallback=True` を無条件で渡し、
「明示指定時はフォールバックしない」という原則が破られていました。

**同じ誤りを繰り返さないでください。**回帰テストも追加すること。

## Step 4 — ベンチマークへの組み込み

**Phase 6a でバックエンド横断の測定基盤を作りました。**

- 新しいバックエンドが**最小の変更で追加できる構造**になっているはずです
- なっていない場合、その事実を記録し、必要な改修を行う
- **実行可否の判定**（利用可能 / 準備が必要 / ハードウェアなし）に対応する

### 測定

**この機（Intel 機）で実測してください。**

| 音声長 | 比較対象 |
|---|---|
| 180秒 | vulkan 1149 / ovvk 827 |
| 900秒 | vulkan 1594 / **ovvk 1733** |
| 3600秒 | vulkan 1451 / **ovvk 1777** |
| 10363秒 | vulkan 1358 / **ovvk 1700** |

**デバイス（CPU / GPU / NPU）ごとに測定してください。**

**NPU での測定が特に重要です。**他のバックエンドは NPU を使えないため、
**NPU で優位に立つ可能性があります。**

### 精度

Phase 6a で CER の測定基盤があります。**速度と併せて測定してください。**

**速いが精度が低い**という可能性を排除するためです。
