## E-1 — セグメント境界を形態素境界へスナップする（最優先）

### 事実

**話者交代境界 77件のうち 22件（28.6%）が、語または句の内部に落ちています。**

| 分類 | 件数 |
|---|---|
| A. 形態素内部での分断 | 9 |
| B. 語境界だが句内部での分断（付属語で始まる） | 11 |
| C. 接頭辞・補助動詞での分断 | 2 |

**原因が特定されています。**

> 形態素内部の9件は、**9件すべてで「跨いだ形態素の左側にちょうど1文字」が残る。**
> ずれ幅が例外なく ASR トークン1個分であり、
> 時間ベースの閾値ではなくトークン境界の扱いに起因することを示します。

> **22件すべてで前後セグメントの gap が 0.02秒以下**（大半が厳密に 0.00）。
> 無音の手がかりがない位置でのみ発生しています。

**時間の問題ではありません。言語の境界を見ていないことが原因です。**

### 発生位置の傾向

| 位置 | 件数 |
|---|---|
| 了解・謝辞・謝罪などの定型応答の内部 | 11（50%） |
| 疑問文終止形の直後 | 5 |

### 実装方針

**評価者の提案:**

> 話者境界の候補時刻を確定する前に、その位置が形態素境界かを判定し、
> そうでなければ最近傍の形態素境界へ移す。
> 単語タイムスタンプは最大11トークンを共有するため、
> **時刻ではなく文字位置を基準にする**必要があります。
> 移動方向は、「遅い」偏りが2倍であることから、前方（早める方向）を優先すると
> 当たりやすいと考えられます。

**これだけで境界誤り率は 28.6% から1桁台まで下がる見込みとされています。**

### 形態素解析器

**SudachiPy を使用してください。**

- 辞書は **`sudachidict_core`** を基本とする
  （用途は「語の境界を知ること」のみ。固有名詞の網羅性は不要）
- **分割単位は A（最小単位）を基本**とし、実測で B との比較を行う
  細かく切るほど境界の候補が増えるため、A が適切と考えられるが、
  **実測で確認して判断すること**
- 依存を追加する extras を判断する
  （**GUI の venv には入れないこと。**推論プロファイル側に入れる）
- **導入されていない環境での挙動を決める**
  - スナップを行わず、従来どおり動作する
  - その旨を警告する
  - **エラーにして処理を止めないこと**

### 言語による分岐

**この処理が必要なのは日本語などの分かち書きしない言語だけです。**

英語では空白で語が区切られるため、形態素解析は不要です。

- 言語設定に応じて処理を切り替える
- 英語では既存の語境界をそのまま使う
- **`--language auto` の場合の扱いを決める**

### 実装上の注意

- **文字位置を基準にすること。**時刻では判定できません
  （同一時刻を最大11トークンが共有するため）
- スナップにより、**セグメントの時刻も更新する必要があります**
- スナップの移動距離に上限を設けるかを判断する
  （遠くまで移動すると、別の誤りを生みます）
- **移動した事実をログに記録する**（件数と移動距離）

## E-2 — 単語時刻なしセグメントの時刻伸長を抑制

### 事実

**bugfix-d で作り込んだ副作用です。**

| 項目 | 値 |
|---|---|
| 単語時刻を持たないセグメント | 33件（27.7%） |
| その合計時間 | **509.0秒（発話区間の 35.1%）** |
| 最悪の例 | **10文字 / 66.16秒** |
| 終了時刻が次セグメント開始と厳密一致 | 33件中10件 |

**文字列は妥当で、時刻だけが壊れています。**

bugfix-d で「本文を保持し、単語時刻だけを破棄する」判断は正しかったのですが、
**セグメントの時刻範囲がそのまま残っているため、無音区間まで話者ラベルが伸びています。**

> 時刻を根拠に発言者を確定する用途では、この3分の1の区間が信用できません。

### 実装方針

**評価者の提案:**

> 単語タイムスタンプを持たないセグメントは、
> 文字数 × 想定発話速度（本データでは 5〜6文字/秒が妥当）で上限を設け、
> 超過分は無音として切る。または VAD の発話区間と交差を取る。

**どちらを採用するか、または両方かを判断してください。**

- **VAD との交差のほうが原理的に正確**です
  （実際の発話区間が分かるため）
- VAD の speech 区間を取得できるかを確認してください
  （whisper.cpp v1.9.2 で `#3916` により内部 VAD の speech segment が
  公開されているとの情報があります。**自分で確認すること**）
- 取得できない場合、文字数ベースの上限で対処する
- **想定発話速度は実測で決めてください。**5〜6文字/秒は今回のデータでの観察値です

### 注意

**切りすぎないこと。**bugfix-d で発話を復活させた成果を損ないます。

- 切った時間の合計をログに記録する
- coverage が大きく下がらないことを確認する
- **97.8% という現在の coverage を維持すること**

## E-3 — 信頼度の低い区間の明示

### 事実

**UNKNOWN が 0件になった副作用です。**

> 判別困難区間も強制的にラベル付けされています。
> 特に E-2 の 509秒に断定的なラベルが付くのは、下流で
> 「発言単位で正確な話者名を付ける」際に誤りを見逃す原因になります。

### 実装方針

**単語時刻がないセグメントは、話者の確定根拠が弱い**という事実を、
出力に反映してください。

以下を検討し、判断してください。

| 案 | 内容 |
|---|---|
| A | 該当区間を `UNKNOWN` にする |
| B | 話者ラベルは付けるが、**信頼度が低い旨のフラグ**を JSON に持たせる |
| C | 出力形式ごとに扱いを変える（JSON にはフラグ、SRT には話者名） |

**B または C を推します。**

`UNKNOWN` にすると、bugfix-d で復活させた 509秒の発言が
「誰の発言か分からない」状態になります。**話者の推定は残しつつ、
その確からしさを示す**ほうが実用的です。

**判断と理由を記録してください。**

### JSON スキーマの変更

フラグを追加する場合、`schema_version` の扱いを決めてください。

- 既存の読み取り側（GUI の閲覧機能）が壊れないこと
- バージョンを上げるか、後方互換な追加にとどめるか

## 実装上の注意

### 破壊的変更への配慮

- 既存の venv、モデル、設定、ジョブを壊さない
- **アルゴリズムの変更により、既存ジョブの `config_hash` が変わります**
- **SudachiPy の追加により、プロファイルの再構築が必要になります。**
  利用者への案内を検討してください
- bugfix-c、bugfix-d の成果を壊さない
- Phase 5a〜bugfix-d の機能を壊さない

### 機密データ

- 実データの文字起こし内容を記録しない
- 形態素解析の結果も、件数のみを記録する
- `.env` を読み取らない

### コミット

- ブランチ `fix/phase-bugfix-e-boundary-snapping`
- 段階ごとにコミットする
- `git push` は実行しない
- 実データ、ビルド成果物、辞書ファイルをコミットしない
