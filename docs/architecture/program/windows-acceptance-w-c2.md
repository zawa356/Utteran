# W-C2 — Windows実機受入指示書（束C2a・C2b: 履歴の非表示・成果物ビュー・複数ジョブUI）

更新: 2026-11-16 JST（開発版`0.1.55`＝束C2a、`0.1.56`＝束C2b）。実施者: Codex／専用Windows 11 VM。
設計: [../b7/history-visibility.md](../b7/history-visibility.md)、[../ui3/s5b-multi-job-board.md](../ui3/s5b-multi-job-board.md)。前提の受入: [windows-acceptance-w-a1.md](windows-acceptance-w-a1.md)。

> **本書は手順書であり、結果ではない。** Cloud工程ではWindows実機・WebView2・実モデルを一切実行していない。
> 実ユーザーのdata root・既定のユーザー領域・既存データのあるディレクトリでは**実行しない**（control DBが一方向に移行する）。
> 音声・転写本文・実パス・tokenを報告やログへ貼らない（件数・状態・固定codeだけ）。**この束に削除機能は無い。削除操作を試さない。**

## 0. 目的と合否

1. 複数ファイルを1回で投入でき、全件が成功する（全件か無しか）。
2. キューと履歴が「論理ジョブ」（再試行は同じ行）で表示され、取消・再試行が効く。
3. 履歴の非表示/再表示で**ジョブ・成果物が何も変わらない**。
4. 成果物ビューが形式別に`verified`になり、編集・差替えを検出する。
5. control DBがv6→v7へ移行し、起動時backupから旧buildへ戻せる。

GPUは対象外。

## 1. 前提

| 項目 | 条件 |
|---|---|
| checkout | 束C2bのDraft PRのHEAD（SHAを記録）。`git status`がclean |
| data root | **この受入専用の新しいroot**（例: `%LOCALAPPDATA%\Utteran-C2-WinVM\data`）。W-A1のrootを流用する場合は、失ってよい合成データだけであること |
| 環境変数 | 親シェルから`UTTERAN_DATA_ROOT`等を継承していないことを確認してから、このシェルだけで設定 |
| profile・モデル・B4証拠 | W-A1と同じ（`setup.ps1 -Profile cpu`、`large-v3-turbo`、fw-cpuのsmokeを取り直す）。**profile venvはこのcheckoutから作り直す**（workerとのIPCに項目が増えているため、古いvenvは要求を拒否する） |
| 入力 | 合成音声を3つ以上（名前を変える。1つは数十秒かかる長さ）。実録音を使わない |
| frontend | `frontend`で`npm ci`→`npm run build`（`--next-ui-v1`は`src/utteran_gui/web-next`のbuildを配信する） |

## 2. 手順

### 2.1 自動試験（Windows上）

```powershell
uv sync --extra dev --extra gui --locked
uv run --no-sync pytest -m "not requires_model" -q tests/test_history_visibility.py tests/test_job_output_dir.py tests/test_b7_b3_model_route.py
cd frontend; npm test; cd ..
```

期待: 全件passed（件数を記録）。

### 2.2 layout v6→v7の移行とbackup（データ保護）

1. **束C1のHEAD（0.1.54）**で`utteran-gui --next-ui-v1`を1回起動し、合成音声を1件投入して`succeeded`まで確認して閉じる（v6のstoreができる）。
   0.1.54のcheckoutを用意できない場合はこの節を「未実施」と記録し、2.3以降を新しいrootで行う。
2. `<root>\data\control-v1\operations.sqlite3`の更新日時とサイズを記録。
3. **束C2bのHEAD**で同じrootを起動。期待: 起動する、手順1のジョブが履歴に見える（状態`succeeded`のまま）、
   `control-v1`に`operations-pre-v1-<時刻>.sqlite3`が増えている。
4. 閉じて、0.1.54のcheckoutで同じrootを起動。期待: **起動を拒否**する（`store_schema_unsupported`。ファイルは変更されない）。
5. 復元ドリル（コピー上で）: 手順3で増えたbackupを別フォルダへ`operations.sqlite3`としてコピーし、0.1.54のcheckoutでそのフォルダをrootにして起動 →
   手順1のジョブが見えること。**元のrootのファイルは上書きしない。**

### 2.3 複数ファイルの一括投入（Expert）

1. Expertへ切替。Preset/Policyを選択（無ければ作成）。合成音声を3件追加し、全選択。
2. 「① まとめて確認」→ 全件が実行可能と表示 → 「② 3件を投入」。
   - 期待: 「3件を受け付けました」。DevToolsのNetworkで`POST /api/v1/jobs`が**1回**、旧`POST /api/jobs`は0回。
3. キューが停止中なら「キュー実行を再開」。期待: 3件とも`完了`になり、履歴へ移る。行の見出しに各ファイル名が出る。
4. 出力先に、ファイルごとの専用ディレクトリが3つでき、それぞれ同名の成果物がある（W-A1 手順6cと同じ規則）。
5. **ファイル別設定**: 1件だけ選択して言語か出力形式を変え「選択中の1件に適用」→「すべて選択」に戻して確認・投入。
   期待: その1件だけ設定が違う成果物になる（形式を変えた場合はファイルの種類で確認）。
6. **拒否**: 1件にファイル別のデバイスを指定 → 「まとめて確認」が押せず、理由（デバイスはファイル別に指定できない）が表示される。Networkに書き込み要求が出ない。
7. 確認後に1件のチェックを外す → 「確認後に…変わりました」が出て投入できない。

### 2.4 キュー・取消・再試行（論理ジョブ）

1. 長めの合成音声を1件投入し、`実行中`になったらその行の「取消」。期待: `取消中`→`取消済み`で履歴へ。成果物の専用ディレクトリは所有markerだけ（自動では消えない）。
2. その行の「再試行」。期待: **同じ行**がキューへ戻り「試行 2回」と表示。内部ジョブIDは新しい値になる。
3. 完了まで待つ。期待: 同じ行が`完了`、「試行 2回」。出力先には**2つ目の専用ディレクトリ**ができ、1回目のディレクトリ（markerのみ）は残る。
4. アプリを閉じて再起動。期待: キュー・履歴が再表示される（ファイル名は「このページで追加していないファイル」と表示され、内部ジョブIDと状態は同じ）。

### 2.5 履歴の非表示/再表示

1. 履歴の1行で「非表示」。期待: 行が消える。**出力先の専用ディレクトリと成果物の更新日時・サイズが変わっていない**（Explorerで確認）。
2. 「非表示の履歴も表示」をオン → 「非表示の履歴」にその行が出る → 「再表示」→ 履歴へ戻る。
3. 再試行した行（2.4）を非表示 → 再表示。期待: 行全体（試行2回）がまとまって消え、まとまって戻る。
4. 実行中・待機中の行には「非表示」が無い（キュー側には出ない）。
5. Networkに`DELETE`が1つも無いこと。

### 2.6 成果物ビュー

1. 完了した行で「成果物を確認」。期待: 形式ごとに「完了時の記録と一致」。**ファイル名・パスは表示されない**。
2. その行の専用ディレクトリのSRTをメモ帳で1文字変えて保存 → もう一度「成果物を確認」。期待: SRTだけ「完了後に内容が変わっています」。
3. SRTを**同じジョブのMD（またはJSON）の内容で上書き**（コピーして拡張子を合わせる）→ 再確認。期待: SRTは「変わっています」のまま（別形式の正しい内容でも一致扱いにならない）。
4. 専用ディレクトリに無関係のファイルを1つ置く → 再確認。期待: 「Utteranが書いていないファイルが1件」。
5. 専用ディレクトリの名前を変える → 再確認。期待: 「専用のフォルダが見つかりません」。名前を戻すと元に戻る。
6. **0.1.54で作ったジョブ**（2.2）: 期待: 成果物は表示されるが「照合できる記録がありません」（形式別の記録より前のジョブ）。

### 2.7 WebView2固有の確認

- IME: Preset名・出力先の入力で日本語変換が途中確定しない。
- 表示倍率125/150/200%とウィンドウ幅を狭めたとき、Expertの3ペインと一覧が読める（横スクロールで操作不能にならない）。
- Explorerからの複数ファイルのドラッグ&ドロップで入力に追加され、一括投入できる。
- 既定起動（引数なし）で旧GUIが従来どおり開き、専用root以外にcontrol DBが作られない。

