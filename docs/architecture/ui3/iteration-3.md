## 2. 可読性の基準と実装

| 対象 | 第2案 | 第3案 |
|---|---|---|
| ボタン（テキスト） | `size="small"`＋global compact＝**高さ16px・字12px** | 高さ36px・字14px（プロトタイプの`VBtn`既定`density: default`＋small/x-smallの下限CSS） |
| アイコンボタン | 20〜28px | 40px角 |
| chip | x-small＝高さ12px・字10px | 高さ28px・字13px |
| 補助テキスト（`text-body-small`） | 12px | 13px（13px未満は作らない） |
| 本文・欄・リスト | 14px前後 | 14〜16px（入力欄・ラベル・タブ・リスト15px、アラート15px） |
| 入力一覧の行 | 28px・13px | 36px・14px。狭いペインでは形式→長さを隠し、さらに300px未満で状態を**アイコンのみ**（文言はtooltipと読み上げ） |
| 字間 | Vuetify既定（英字向けletter-spacing） | 日本語が間延びしないよう`letter-spacing: normal` |

- 本番`src/styles/theme.ts`の`componentDefaults`（global compact）は**変更していない**。プロトタイプは`previewDefaults`で上書きした。本番へ入れる場合は
  S1で全画面のボタン高さが変わるため、別PRでUI-2画面の再確認と合わせて判断する（§11）。
- 文字を縮めて収める処理は無い。幅が足りない時は「格納（メニュー化）」「列を隠す」「アイコン化（文言はtooltip/読み上げ）」「折り返し」で対応した。

```text
┌ Utteran ファイル 表示 ツール ヘルプ │ 文字起こし セットアップ 設定 ………… [通常|Expert] ┐
│ ⚠ 試作版（UI-3-0 第3案） 表示は合成データです。文字起こし・保存・ファイル操作・通信は行いません。 │

│ │ sample-meeting-01.wav   │ │ ✓文字起こし ▶話者分離 ○出力              │                  │
│ │ WAV · 12:34             │ │ 工程 2/3: 話者分離            この工程 50% │                  │
│ │ [別のファイルにする…]   │ │ ██████████░░░░░░░░░░                       │                  │
│ ├設定 ───────────────────┤ │ 経過 2:10  この工程の残り 約2分（推定）    │                  │
│ │ 言語  話者分離  出力形式 │ │ [× 取消]                                   │                  │
│ │ ▸詳細（モデル・話者数） │ │ ┄ デモ操作 [進捗を進める][次の段階へ][失敗させる] │          │
│ └─────────────────────────┘ └────────────────────────────────────────────┘                  │
└ ┄┄ レビュー用操作（製品UIではありません）▾ ┄┄┘
```

- 開始できない時だけ理由を1行（ファイル未選択・未対応形式・環境の準備ができていない＋「セットアップ」）。CPUのみの例では「CPUで実行します。長い音声は時間がかかります。」
- 完了後は出力ファイル名、「出力フォルダを開く」（無効、理由はtooltip）、「別のファイルを文字起こし」。Expertへの誘導文は出さない。
- **選択規則**（画面には説明しない）: 通常が表示する1件＝最後に選んだ／触れた入力 → 選択中の先頭 → 一覧の先頭。「別のファイルにする」は新ファイルを表示対象にし、
  古い入力は「唯一・未投入・個別設定なし」のときだけ外す。Expertの入力・ジョブ・override・履歴を削除・上書き・取消する操作は通常には無い（確認が要る操作を作らなかった）。

## 4. Expertの左→右フローと比率の所見

- 見出し①②③は同じ部品（`PaneHeading`）で、番号の丸・字の大きさ・下線・余白を揃えた。矢印やウィザードは使っていない。1列表示のペイン切替も「1 ファイル／2 処理設定／3 キュー投入」。
- 件数の一致: ①「選択中: n」＝②「対象: n」＝②タブ「選択したn件」。③のボタンは「選択したm件をキューへ投入」で、m＝選択のうち投入できる件数。
  m<nのときは「選択のうちk件は投入済みか未対応の形式のため、投入しません。」、m=0のときは理由（未選択／すべて投入済み／未対応）を表示。
- 投入後: ボタン直下に「n件をキューに追加しました。」（除外があれば件数と理由）、下段の簡易キュー先頭に追加分が**左線＋薄い下地**で現れる（別ページへ行かずに確認できる）。
  選択を変えると結果表示は消える。簡易キューは最大5行で内部スクロール、6件目以降は「キューを開く（ほかn件）」。検索・並べ替え・順序変更・詳細はキュー画面だけ。
- ペインのF6移動・区切りのdrag/キーボード/ダブルクリック・Enterリセット、サイドバーの幅・上部の折りたたみ、作業領域幅での3→2→1列は第2案から**退行なし**（E2E）。
  「ペイン幅をリセット」の常設ボタンと「F6で…」の説明行は撤去し、表示メニュー「ペインの幅を元に戻す」と区切りの操作に集約した（キー操作の説明は区切りと一覧の読み上げ名に残す）。

**比率の所見（確定ではない）**

## 5. 処理状況の表示（バックエンド同期を意識させない）

| 状態（レビュー帯「処理状況の取得（例）」） | 製品画面の表示 | 表示場所 |
|---|---|---|
| 正常（既定） | なし | — |
| 確認に時間がかかっている | 「処理状況を確認しています…」1行（小さな回転表示）。**実行中のジョブがある時だけ** | 通常の実行カード、Expertの簡易キュー、キュー画面 |
| 取得できない | 警告「処理状況を取得できません」「表示は最後に取得した状態です。処理が止まったとは限りません。」＋再試行 | 同上 |

- ジョブの状態chip（実行中など）は最後に取得した値のまま変えない。「停止」「失敗」とは表示しない（Vitest・E2Eで検査）。
- サイドバー・ヘッダ・ワークスペースに接続・同期・epoch・`/sync`・SSEの語は出さない（製品文言の辞書をVitestで検査）。
- 本番のB9 SSE/API・Workerは変更していない。実装時は「SSEの再接続中」「`/sync`での置換中」を同じ2状態に写像し、遅延が数秒続いた時だけ1行を出す（短時間の再同期は無表示）。

## 6. 共通メニュー、ログ・診断・ヘルプ（モック）と実装時の注意

- メニュー: ファイル（通常＝ファイルを選ぶ…／Expert＝ファイルを追加…・フォルダを追加…）、表示（通常／Expertモード、Expertではペインの幅を元に戻す）、
  ツール（システムログを見る／文字起こしジョブのログを見る／診断情報をエクスポート…）、ヘルプ（Utteranについて／GitHubのリポジトリを開く）。
- 比較: レビュー帯の「メニューの形」で**メニューバー**（Windowsアプリ風）と**メニューボタン**（1つに集約）を切替。1100px未満は常にボタン。
- ダイアログは各1回「デモ（サンプル表示）」chipを出す。ログは固定のサンプル行（ジョブログはデモジョブの状態から生成、ファイル名は含めない）。
  診断のエクスポートは無効ボタン＋「試作ではファイルを作成しません」。何も読まず、書かず、送らない（E2Eの通信・console検査で確認）。
- 「Utteranについて」: 名前、バージョン「0.1.43（未リリースの開発版）」＋「開発版の試作」chip＋「正式な配布版のバージョン情報ではありません」、MIT License、
  リンクは`https://github.com/zawa356/Utteran`とその`LICENSE`・`THIRD_PARTY_NOTICES.md`だけ（E2Eで全リンクの接頭辞を検査）。公式サイトは記載しない。

**実装時の注意（ログ種別・範囲・マスキング）**

| 種別 | 正本（現状） | 範囲 | 表示・出力の規則 |
|---|---|---|---|
| システムログ | GUIの`logging_runtime.py`（JSON行、保存日数・サイズ上限あり） | アプリの起動・画面・環境読み込み・キュー・状況取得の失敗/回復 | 段階名と値なしのフィールドだけ。tokenは「設定済み」のみ |
| ジョブのログ | job_runtime / worker（ジョブ単位） | 受付・準備・工程開始/終了・失敗コード・取消 | 入力・出力は`<入力ファイル>`/`<出力先>`等の置換表記。本文・音声は記録しない |
| 生のサブプロセスログ | `raw_subprocess_logs`（既定オフ） | 推論ライブラリの標準出力 | 診断エクスポートに**含めない**（パス・本文が混ざり得る） |
| 診断情報 | 未実装 | 版・OS・環境の概要・直近ログ（伏字済み）・設定項目名と既定値からの変更有無 | フルパス、音声・動画、文字起こし本文、トークン・パスワード、プロンプト・用語ヒントは**含めない**。保存前に内容を一覧で確認させる |

伏字の規則の例として`maskForDiagnostics`（Windows/Unixのホーム配下パス→`<path>`、`hf_`トークン→`<token>`）をVitestで固定した。
実装時は許可リスト方式（出力してよいフィールドだけを列挙）を正とし、置換は二重の安全策に留める（[AGENTS.md](../../../AGENTS.md)のPrivacy）。

## 8. 進捗率・推定残り時間（mock）とバックエンドの次の作業候補（G-03）

**mockの表示規則**: 工程の位置（2/3）と名前、その工程の進捗%（バックエンドが報告する値の想定）、経過時間、その工程の推定残り（「（推定）」と明記）。
10%未満または経過0なら「残り時間を推定中」。進捗を報告しない工程（出力、準備中）はindeterminateで%も残りも出さない。**ジョブ全体の%は固定の工程重みから作らない。**
値はすべて架空で、デモ操作（進捗を進める＝+25%・+45秒、次の段階へ）でだけ動く。

**既存実装で確認した事実**（読んだだけで変更していない）

- `src/utteran/asr/faster_whisper.py`: セグメント終了秒と音声長で`ProgressEvent("asr", current, total, …)`を出す。
- `src/utteran/asr/whisper_cpp.py`: 標準エラーの`progress = n%`を`parse_progress`で解析。
- `src/utteran/diarization/pyannote.py`: pipelineの`hook(step_name, …, total, completed)`から進捗を得る。
- `src/utteran/worker_runtime.py`: これらを`WorkerProgress(stage, state, fraction∈[0,1] | None)`としてworker IPCへ送る（`utteran_contracts/worker.py`）。
- **B9 v1 SSEはprogressを配信しない**（[backend-gap-matrix](../ui1/backend-gap-matrix.md) G-03）。

**G-03の提案（別PR・owner承認後）**

1. 契約: 永続化しない一時イベント`job.progress {job_id, stage, stage_index, stage_count, fraction|null, elapsed_ms}`。DBに保存せず、`/sync`には最新1件だけを含めるかを決める。
   stage_countはsnapshot（話者分離の有無）から決まる。
2. 間引き: workerは高頻度で出すため、GUI側で工程ごとに最大1〜2回/秒へ間引く。fractionは単調非減少にclampし、工程が変わったら0から。
3. ETA: その工程の経過時間と`fraction`から外挿し、**指数移動平均などで速度を平滑化**する。開始直後（例: 10%未満・10秒未満）は出さない。
   VAD・モデル読み込み・話者分離のクラスタリング等で速度が大きく変わり、**推定は増えることもある（非単調）**ため、表示は「約n分」と丸め、急変時は「推定中」に戻す。
4. ジョブ全体の残りは、工程ごとの実測比率が蓄積されるまで出さない（固定重みで%をでっち上げない）。

## 11. 未検証・残るUX判断

**未検証**（隠さない）: Windows WebView2での表示・操作・ドラッグ、OS DPI実機（125/150/200%）とWindows日本語フォント、IME（自由入力欄なし）、native file picker・D&D、

**ownerに判断してほしい点**

1. 可読性の下限（ボタン36px・文字13px以上）を本番`componentDefaults`へ入れるか（入れるとUI-2画面全体の高さが変わる。S1で一括か画面ごとか）。
2. Expertの既定比率: 1280pxで22/53/25はファイル名が約12文字で切れる。幅で比率を変えるか、ファイルペイン最小幅を上げるか、30/42/28へ戻すか（§4）。
3. メニューの形: メニューバー（ファイル／表示／ツール／ヘルプ）とメニューボタンのどちらを既定にするか。通常モードでもメニューバーを見せるか。
4. 通常の「別のファイルにする」: 古い入力を外す条件（唯一・未投入・個別設定なし）と、それ以外は残して見せない挙動でよいか。通常に「一覧から外す」操作が無いことの是非。
5. 通常の設定欄が「表示中ファイルの個別設定があればそれを変える」挙動でよいか（Expertの共通既定値は変わらない）。
6. 処理状況「確認中」を出すまでの遅延（実装時は数秒）と、取得不可の警告の置き場所（実行カード・簡易キュー・キュー画面）。
7. 進捗表示の粒度（工程内%＋その工程の残り）で足りるか。ジョブ全体の残りを将来出す条件（§8-4）。
8. 設定のカテゴリ（一般／ログと診断／高度な動作／プリセット）と、プリセットをどこで編集するか（設定ページかInspectorか）。
