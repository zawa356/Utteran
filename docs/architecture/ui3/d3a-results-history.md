# UI-3 D3-A Expertの結果・履歴

開発版 0.1.61、未リリース。基点は main `5ade41ad59f488eb7004759a69dc4a7100cd0ebd`（PR #67）。設計は [Design Freeze §7](design-freeze.md#7-追補2026-11-16-owner確定-内部job-idと論理ジョブ)、[B7可視性](../b7/history-visibility.md)、[C2c削除](../program/c2c-deletion-design.md) の現行実装に従う。

## 画面とAPI

- `--next-ui-v1` のExpert 「結果」で、結果と履歴の2タブを表示。結果は全枝が終了しており表示対象の最新内部Jobが成功した論理Job。履歴は全終端状態を表示し、表示順・状態・Job ID／セッション内のbasenameで絞り込める。
- 全件一覧からサーバー順序とretryグラフを確定し、同じJob集合revisionの可視一覧で表示対象を選ぶ。可視／非表示に同一チェーンがまたがっても、表示する試行は選択中の区分だけで、論理ルートと未完了枝の判定は共通。非表示によりJobListのrevisionは進まない。ページングの重複・失敗・revision交差では一覧と詳細を消す。B7の実行順序はキューの応答から取得する。
- ページ間で `core.v1.board` と参照カウント式のwatchを共有。結果ページは明示更新を持つ。行選択は論理ルート、詳細は最新の読み取りから解決する。タブや可視区分を切り替えた時と、行が消えた時に選択を解除する。
- retryは可視の終了行の最新内部Jobを対象に、同一snapshotを持つ新しいB7内部Jobを作る。未完了中は同じ論理ルートがキューに戻る。rerun由来は別論理ルートとして表示する。
- 非表示／再表示は全内部Jobに既存のvisibility CASを順次適用する。途中で停止した要求は元の対象・本文・If-Matchを保持し、明示再照合で既に反映した状態を確認するか、同じPUTを送る。412後は再読込して次の意思決定を待つ。
- C2cの履歴削除は各試行から対象を明示して、plan・保持範囲の確認・executeを行う。planは明示操作による読み取り専用のPOST。executeの結果不明中は共有gateと再照合コンテキストを保持する。履歴レコード削除後も関連Jobと出力は保持する。
- ③に投入・単件状態・簡易キューと専用画面への導線を残す。試作の「片付ける」はB7が終端に達した項目をキューから自動で外すことで満たす。外観の最終調整とWindows WebView2受入はD4。
- 成果物は最新内部Jobのメタデータを明示操作で読む。出力ファイルの削除は全OSで無効（#59）。[D3-B](d3b-artifacts-rerun.md)で現在設定の再実行を接続し、外部閲覧は安全性の制約でBLOCKED。内蔵Viewerは今回の対象外。ASRなしの再出力は束Eへ移管。

成果物削除を要求できた旧試験ID `v1-board-delete-artifacts` は、操作を露出しない仕様に合わせて不存在を検査する。拒否された計画と実行は引き続き実HTTPを検査する。複数試行の削除は各試行のボタンからIDを明示するため、旧ダイアログのradio用試験IDを廃止。S5-B/Cの旧行内の操作試験は履歴タブの選択詳細へ移設した。

試行データはすべて合成。Linux Chromiumでの機能と表示を確認する。OS固有のIME確定やネイティブダイアログ、WebView2はブラウザー試験で代替しない。
