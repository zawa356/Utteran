# D4-B 製品画面の表示と操作

D4-A のレイアウト上で、開発専用 v1 の表示密度と日英の操作名を揃えた。元の API 実装、レコード、ジョブの状態遷移は [D2-B](d2b-queue-actions.md)・[D3-A](d3a-results-history.md)・[D3-B](d3b-artifacts-rerun.md) を参照。

| 画面 | 表示と操作 |
|---|---|
| Normal | 入力・共通設定から、確認と投入へ。実行側は B7 が返した状態をアイコンと文言で表示する。投入後の受付、実行中、完了はそれぞれの状態を表示する。 |
| Expert ①②③ | ペイン名を固定表示。共通 Preset／実行 Policy と選択ファイルの設定を区別。簡易キューは先頭5件と全件画面への導線。単件操作の再照合・追跡は展開して使う。 |
| キュー・結果・履歴 | 長い一覧は表内スクロールにしてヘッダを固定。詳細は B7 の内部ジョブ、版、理由を保持する。読み取りエラーは空一覧と区別する。 |
| 設定・実行環境 | 既存のライト／ダーク／システムとは独立に青／緑を選べる。青が初期値で、アクセントは起動中だけ適用する。実行環境の観測と、投入前の実行可否の検証を区別する。 |
| 履歴のみ削除・再実行 | Escで未実施の確認を終了し、起点へフォーカスを返す。結果不明の再照合と送信中は既存 controller が閉じる操作を制限する。 |

第5案との主な差は B5 Preset／Policy の選択と B7 確認・投入の二段階、実行工程・進捗率・成果物パスの非提供、履歴のみ削除の可否を実APIの計画結果で示す点。モデル、セットアップ、外部閲覧・成果物削除は後続の提供条件を引き継ぐ。Visual 比較と Windows への引継ぎは D4-C に記録する。
