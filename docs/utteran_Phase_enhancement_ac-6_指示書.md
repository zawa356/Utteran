## Step 1 — A-3: ダイアログの置き換え

### 対象の範囲（確定済み）

**置き換えるのは `alert()` / `confirm()` / `prompt()` のみです。**

**ファイル選択ダイアログは対象外です。**OS のネイティブダイアログを使い続けてください。
ac-3 で実装した入出力ディレクトリの記憶も、ネイティブダイアログを前提にしています。

### 作業

- `app.js` 内の `alert` / `confirm` / `prompt` の使用箇所を洗い出す
- **アプリのデザインに沿ったモーダル**へ置き換える
- **すべての使用箇所を置き換える**（一部だけ残さない）

### 注意点

**`confirm()` は同期的に真偽値を返しますが、モーダルは非同期になります。**

呼び出し側の制御フローが変わります。**この変更で、既存の処理順序が壊れないよう注意してください。**
特に以下は慎重に扱うこと。

- **破壊的操作の確認**（ジョブ削除、プロファイル削除など）
- **ac-2 で実装したプロセス終了に関わる箇所**があれば、その挙動

### モーダルの要件

- **キーボード操作で完結できる**（Enter で確定、Esc で取り消し）
- 背景をクリックしたときの挙動を定義する
- **破壊的操作では、既定のフォーカスを「取り消し」側に置く**
- 多重に開かないこと

### 国際化

`i18n.js` があります。**モーダルの文言を、既存の仕組みに沿って追加してください。**
ハードコードしないこと。

### ac-3 との関係

**`.format-chip` の絶対配置を修正したばかりです。**
モーダルは絶対配置・固定配置を使うため、**既存のレイアウトに影響しないことを確認してください。**

## Step 2 — A-4: 実現可能性の調査（実装の前に必ず行う）

### 背景

**ブラウザの `DataTransfer` API は、セキュリティ上フルパスを返しません。**
ファイル名のみです。pywebview は WebView2 上に載っているため、同じ制約を受けます。

**したがって、フルパスを取得できるかどうかは自明ではありません。**

### 調査すること

- **pywebview の現在のバージョンで、ドロップされたファイルのパスを取得する手段があるか**
- ある場合、その API と制約（複数ファイル、フォルダ、リンクなど）
- **WebView2 のドロップイベントを直接扱う経路が存在するか**
- 取得できる場合、**開発環境と配布版（exe）で挙動が同じか**

### 注意 — 前例がある領域です

**Phase 5 系で `window.native` の再帰という問題が発生した前例があります。**

pywebview の JS ↔ Python 連携は、**開発環境では動くが exe では動かない**、
あるいはその逆、という差異が生じやすい領域です。

**開発環境だけで「できる」と判断しないでください。**

### 判定

| 判定 | 条件 | 次の扱い |
|---|---|---|
| **A** | フルパスを安定して取得できる | Step 3 で実装する |
| **B** | 取得できるが制約がある | 制約を明示して実装する |
| **C** | **取得できない** | **代替案を検討する（Step 4）** |

**判定と根拠を `AISTATE.md` へ記録してください。**

**推測で判定しないこと。**実際に試して確認します。

## Step 3 — A-4: 実装（判定 A / B の場合）

### 求める挙動

- ファイルをドロップすると、**入力欄にフルパスが入る**
- **ac-3 で実装した入力ディレクトリの記憶と噛み合うこと**
  （ドロップしたファイルのディレクトリが、次回の既定になる）
- 複数ファイルをドロップした場合の挙動を定義する
- **フォルダや非対応形式をドロップした場合の挙動**を定義する

### 機密性の注意（重要）

**ac-3 で「入力ファイル名を保存しない」という方針を確定させています。**

**ドロップしたファイル名を、設定やログへ保存しないこと。**
ディレクトリのみ記憶します。

**この方針を崩さないでください。**

### エラーの扱い

- 対応していないファイルをドロップした場合、**理由を示す**
- **黙って無視しないこと**
- ac-1 の原則に従い、**未知の状態を失敗として扱わない**

## Step 4 — A-4: 代替案（判定 C の場合）

**フルパスが取得できない場合、実装せずに終わらせないでください。**

利用者から見た問題は「ドラッグ＆ドロップが使えない」ことです。
**フルパスが取れないなら、別の解決を検討します。**

### 検討する方向（例）

- ドロップを検知したら、**ファイル選択ダイアログを開く**
  （ドロップしたファイルは選べないが、操作の起点にはなる）
- ドロップ領域を廃し、**ファイル選択への導線を分かりやすくする**
- 何もしない（**現状維持。ただし理由を記録する**）

### 判断の基準

**中途半端に動く状態を作らないでください。**

ドロップできたように見えて実際は失敗する、という挙動が最も悪い。
**できないなら、できないと分かる形にします。**

判断と理由を `AISTATE.md` へ記録してください。

- **中途半端に動くドロップ処理を残すこと**
- ac-1 〜 ac-5 の修正を壊すこと
- `align.py` と Viterbi に変更を加えること
- **exe とポータブル版での確認を省略すること**
- 実データ（`input/`）を使用すること
- マイナーバージョンを独断で上げること
- `git push` を実行すること

## 不明点があった場合

1. `要件定義.md` と既存実装を優先する
2. 判断できない場合、**安全側に倒し、記録する**
