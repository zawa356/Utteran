## 確定した調査結果（前提）

再調査は不要です。以下は実機で確認済みです。

| 項目 | 結果 |
|---|---|
| 日本語の単語時刻 | **取得不可**。130文字・118トークンが1時刻要素に融合 |
| 原因 | 公式実装が DTW 後に**無条件でスペース分割**している |
| トークン別時刻の取得 | **公開 API に存在しない** |
| 英語の単語時刻 | **正常**。18語、平均 5.89 文字/語 |
| phrase 単位の時刻 | 取得可能（短尺検証で 130文字あたり5区間） |
| モデル | MIT、非 gated、約 828 MB、int8 量子化 |
| torch との衝突 | **なし**。XPU 版 torch 2.11.0 は維持される |

### 速度（推論のみ、ロード除く）

| デバイス | ロード | 180秒 | 900秒 |
|---|---:|---:|---:|
| CPU | 1.742秒 | 353 | 394 |
| GPU | 8.983秒 | **1367** | **1748** |
| NPU | 281.254秒（キャッシュ後 2.6秒） | 585 | 595 |

比較対象（Phase 6a・同一機）: ovvk 827 / 1733、vulkan 1149 / 1594

### NPU キャッシュ

初回ロード 281秒 → キャッシュ後 2.6秒。**容量は約 2.06 GiB。**
`CACHE_DIR` で utteran 管理下へ配置可能。

## 実装方針（確定事項）

**「バックエンドの選択肢は可能な限り増やす。ただし、そのデバイスにとって最適かどうかは
測定に基づいて別途判断する」という方針に沿って、実装します。**

### 位置づけ

GenAI は「ネイティブビルドを必要としない GPU 経路」です。
whisper.cpp が cmake / MSVC Build Tools / Vulkan SDK を要求するのに対し、
GenAI は pip で導入できます。

### 5つの確定事項

| # | 決定 | 理由 |
|---|---|---|
| 1 | **日本語かつ話者分離ありでは選択させない** | 単語時刻が取得できず、割当精度が bugfix-c 以前へ後退するため |
| 2 | **英語・話者分離なしでは制限なく使える** | 単語時刻が正常。機能上の制約がない |
| 3 | **auto では選ばせない** | 最適化の判断は 6c の範囲 |
| 4 | **NPU は CLI で常に指定可、GUI は「非推奨の構成を表示する」の内側** | 動作するが遅く、2.06 GiB を消費するため |
| 5 | **将来の解除条件を記録する** | 上流が非スペース言語に対応すれば制限を外せる |

### 採用しなかった案（記録）

**phrase 区間（約26文字）を単語時刻の代用とする案は採りません。**

- 実データでの区間長が未測定
- `Word` 型に「単語ではない区間」を混入させることになる
- **bugfix-c〜f で積み上げた align.py と Viterbi に回帰リスクを持ち込む**
- 上流が対応した時点で不要になる作り込みである

**この判断と理由を `AISTATE.md` に記録してください。**

## Step 1 — バックエンドの実装

`src/utteran/asr/openvino_genai.py` を作成します。
`whisper_cpp.py` と `faster_whisper.py` が実装例です。

| メソッド | 実装内容 |
|---|---|
| `is_available()` | 必要なパッケージの有無。**import 失敗を握りつぶして False** |
| `available_devices()` | OpenVINO の利用可能デバイス（CPU / GPU / NPU） |
| `load()` | モデルとデバイスの解決、パイプライン初期化、**キャッシュ設定** |
| `transcribe()` | 認識の実行、**共通型への変換** |
| `unload()` | 解放 |

### 守るべき原則

- **バックエンド固有の型を上位層に漏らさない。**戻り値は `TranscriptionResult`（`Segment` / `Word`）
- 進捗コールバックとキャンセルトークンを実装する
- **明示指定時はフォールバックしない**（`auto` のときのみ退避）
- モデルの暗黙ダウンロードを行わない

### レジストリへの登録

`src/utteran/asr/registry.py` に登録します。

**Phase 5j で、`registry.py` が `allow_fallback=True` を無条件に渡し、
「明示指定時はフォールバックしない」という原則が破られていた前例があります。**

同じ誤りを繰り返さないこと。**回帰テストを追加してください。**

### 退化した単語時刻の検出（重要）

英語であっても、モデルや設定によっては単語時刻が退化する可能性があります。

**`transcribe()` の中で、以下を検出して記録してください。**

- 1つの `Word` が担当する文字数が異常に多い場合
  （**目安: 1要素あたり 30文字以上**）
- セグメント全体が1つの `Word` に融合している場合

検出時の扱い:

- **その `Word` を破棄せず、統計量をログへ記録する**
  （何件を退化と判定したか、平均文字数）
- 話者分離が有効な場合、**利用者へ警告する**

**「データを捨てる処理は、何をどれだけ捨てたかを必ず記録する」**という
過去の教訓（bugfix-c の 508秒喪失）に基づく要求です。

## Step 2 — 言語と話者分離による選択制御

**確定事項1 の実装です。本作業の中核であり、最も慎重を要します。**

### 遮断する条件

**以下の組み合わせを禁止します。**

- ASR バックエンドが GenAI である
- **かつ** 話者分離が有効である
- **かつ** 言語が「スペースで区切られない言語」である

### 「スペースで区切られない言語」の判定

原因はスペース分割の実装なので、**対象は日本語だけではありません。**

最低限、以下を対象としてください。

```
ja, zh, th, lo, my, yue
```

**本家 whisper の実装が非スペース言語として扱う集合に準拠します。**
実装時に本家の該当リストを確認し、**根拠を `AISTATE.md` に記録してください。**

### 言語が `auto`（未指定）の場合

**これが最も注意を要する分岐です。**

処理前に言語が確定しないため、事前判定ができません。
**安全側に倒し、話者分離が有効な場合は GenAI を選択させないでください。**

- 言語が明示的に指定され、かつ非スペース言語**でない**場合のみ許可する
- `auto` は許可しない

**「明示指定時はフォールバックしない」原則との関係を明確にしてください。**
これはフォールバックではなく、**組み合わせの拒否**です。
エラーとして扱い、**理由と代替案（whisper.cpp を使う）を提示**してください。

黙って別のバックエンドへ切り替えないこと。

### CLI での挙動

- 禁止される組み合わせが指定された場合、**明確なエラーメッセージで停止**する
- メッセージに理由を含める（単語時刻が取得できないため、話者割当の精度が保証できない）
- 代替手段を案内する

### GUI での挙動

- 話者分離が有効かつ言語が対象の場合、**GenAI を選択肢に出さない**
- **なぜ出ないのかが分かる形にする**（無言で消さない）

## Step 3 — NPU の扱いと「非推奨の構成」

**確定事項4 の実装です。**

### 汎用の仕組みとして作る

**NPU 専用の分岐ではなく、「非推奨の構成」という汎用の枠組みを作ってください。**

将来 B-1（OpenVINO IR 未生成での ovvk 選択）などにも使えるようにするためです。

- 構成に「非推奨」の属性と、**その理由の文言**を持たせる
- GUI に **「非推奨の構成を表示する」というトグル**を設ける（既定はオフ）
- **CLI では常に指定可能**とする（測定・検証で使うため）
- ベンチマークからは常に測定可能とする

### NPU に付与する情報

- 非推奨である旨
- **初回ロードに約280秒かかること**
- **キャッシュに約 2.06 GiB を消費すること**
- キャッシュ後のロードは約 2.6秒であること
- 現時点では GPU の方が高速であること

**数値は本指示の測定値をそのまま使わず、実装後に自機で再測定した値を用いてください。**

### キャッシュの配置

**「利用者の環境を汚さない」という設計方針があります。**

- `CACHE_DIR` を **utteran の管理下**へ設定する
- ユーザープロファイル直下や既定の一時領域へ置かない
- `scripts/reset-env.ps1` の削除対象に**含める**
- **キャッシュの現在の使用量を確認できる手段**を用意する（`models` 系のコマンドが適切か検討）

### 動作しない場合

NPU が存在しない環境では、**選択肢に出さない**（既定方針どおり）。
「非推奨」と「動作しない」は別の概念として扱ってください。

## Step 6 — ベンチマークへの組み込み

Phase 6a の測定基盤へ追加します。最小の変更で追加できる構造のはずです。

### 測定

|---:|---:|---:|

| 3600秒 | 1451 | **1777** |
| 10363秒 | 1358 | **1700** |

### ロード時間の扱い（要確認）

**`benchmark.py` を読み、Phase 6a のスコアがモデルのロード時間を含むかを確認してください。**

- **既存の測定と同じ定義で算出し直すこと**
- **ロード込み・ロード除きの両方を報告すること**
- どちらの定義かを結果に明記すること

**これは比較の妥当性に関わります。定義が揃っていない数値を並べないでください。**

**CER を必ず測定してください。**

検証モデルは **int8 量子化**です。whisper.cpp 側と量子化条件が異なるため、
**速度差が精度差で相殺されている可能性があります。**

Phase 6a の CER 測定基盤を使い、速度と併せて報告してください。

- **`git push` は実行しない**

---

## 不明点があった場合

1. `要件定義.md` と既存バックエンドの実装を優先する
2. 判断できない場合、**安全側に倒し、記録する**
3. 実測できない項目は、推測で埋めず「未確認」と記録する
4. **Step 2 の選択制御で判断に迷う場合、より制限的な側を選ぶ**
   （誤って使えてしまうより、使えないほうが害が小さい）
