# utteran — Phase 5b 実装指示（結果の閲覧・検索・ジョブ履歴）

## あなたへの依頼

Phase 5b として、**GUI での文字起こし結果の閲覧、検索、ジョブ履歴**を実装してください。

着手前に必ず以下を読んでください。

1. `AISTATE.md`
2. `要件定義.md`（特に Phase 5a で追加された GUI の章）
3. `docs/Phase5a_GUI_手動確認手順書.md`
4. `README.md`

作業ブランチは `feature/phase5b-gui-viewer` を新規作成して使用します。

---

## 前提

Phase 5a で以下が完成しています。

- 独立した GUI 環境（`.venvs/win-gui`、推論依存なし）
- FastAPI + pywebview、セッション鍵によるループバック API
- `--progress-json` による機械可読な進捗
- 環境検出、実行設定、進捗表示、キャンセル、出力ファイル一覧
- ダーク／ライト、日本語／英語

**Phase 5a の原則を維持してください。**

- GUI は `utteran` パッケージを import しない
- GUI の venv に推論系の依存を入れない
- 色はコンポーネントに直書きせず、CSS 変数で管理する
- 文言は辞書化し、日本語／英語を切り替えられる

---

## Phase 5b の実装範囲

### 含むもの

- 文字起こし結果の閲覧
- 検索とフィルタ
- ジョブ履歴の一覧と再訪
- 出力ファイルの再生成（形式の変更、話者表示名の適用）

### 含まないもの

- 本文の編集
- 音声の再生と同期
- 話者の再割り当て

これらは Phase 5 の当初スコープ外です。**ただし将来追加しやすい構造にしてください。**

---

## Step 1 — データの取得経路

**GUI は `utteran` を import できません。**結果の取得方法を設計してください。

### 想定される経路

| 方法 | 内容 |
|---|---|
| 出力 JSON を直接読む | GUI が JSON をパースするだけなので、コアへの依存は生じない |
| `jobs list` / `jobs show` の JSON 出力を使う | ジョブ一覧と状態の取得 |

**`jobs list --json` と `jobs show --json` が存在するかを確認し、
無ければ CLI に追加してください。**（`profiles list --json` や
`native status --json` は Phase 5a で追加済みのはずです）

### 中間結果の扱い

ジョブディレクトリには `merged.json` があり、これが最も情報量の多い形式です。
出力先の JSON と比べて、どちらを読むべきかを判断してください。

- 出力 JSON は利用者が指定した場所にあり、削除・移動されている可能性がある
- `merged.json` はジョブディレクトリにあり、レジュームのために保持されている
- **どちらを正とするか、両方に対応するかを決め、理由を記録してください**

### スキーマの互換性

JSON には `schema_version` があります。**GUI が想定するバージョンと異なる場合、
壊れた表示をせず、明確に伝えてください。**

## Step 2 — 結果の閲覧

### 性能要件

**2時間の会議で 1,300 セグメント程度、単語レベルでは数万語になります。**

- **仮想スクロールを実装してください。**全件を DOM に展開しないこと
- 初期表示は 1 秒以内を目標とする
- スクロールが引っかからないこと

長時間の実データで実際に確認してください。

### 表示内容

**セグメント一覧**

- タイムスタンプ（開始・終了）
- 話者ラベル（表示名の設定があれば適用）
- 本文
- **話者ごとに色を割り当てる**（テーマに調和する配色にすること）

**メタ情報**

出力 JSON の `processing` セクションから、以下を表示してください。

- 使用した ASR バックエンド、モデル、デバイス
- 使用した話者分離バックエンド、モデル、デバイス
- 生成日時
- 音声長、セグメント数、話者数

**これは Phase 5a 後に判明した課題への対応でもあります。**
どのモデルで生成された結果かが分からないと、利用者が古い結果を
新しいものと誤認する可能性があります。**目立つ位置に表示してください。**

**統計**

- 話者ごとの発話時間と割合
- 平均ターン長

過剰にならない範囲で、判断して実装してください。

### 単語レベルの情報

出力 JSON には単語ごとのタイムスタンプと確度が含まれます。

- **既定では表示しない**（情報量が多すぎる）
- 必要に応じて確認できる手段を用意するかは判断してよい
- 確度が低い単語を強調する機能は有用かもしれませんが、
  実装するかは判断に委ねます

---

## Step 3 — 検索とフィルタ

### 検索

- 本文の全文検索
- **一致箇所のハイライト**
- 一致件数の表示と、前後の一致への移動
- 大文字小文字の区別、正規表現の可否は判断してよい

**日本語の検索に注意してください。**
IME による入力中（変換確定前）に検索が走ると使いにくくなります。
確定後に実行する、または適切な遅延を入れてください。

### フィルタ

- 話者による絞り込み
- 時間範囲による絞り込み

### 検索語の保存

**検索語を永続化しないでください。**
会議の内容に関する語句が入力される可能性があり、
GUI の設定ファイルに残ると情報が漏れる経路になります。

---

## Step 4 — ジョブ履歴

### 一覧

- 入力ファイル名、日時、状態、使用したモデル、話者数
- 状態による絞り込み（完了、失敗、破損）
- 並び替え

### 操作

- 結果を開く
- 出力フォルダを開く
- ジョブを削除する
- **出力ファイルを再生成する**（後述）

### 削除

- 削除前に対象と解放される容量を表示し、確認を求める
- **現在の `jobs clean` には個別指定の手段がありません。**
  別途調査作業で追加される可能性があります。
  無ければ、この作業で CLI に追加するか、GUI 側で対処するかを判断してください

---

## Step 5 — 出力ファイルの再生成

Phase 2 で実装済みのレジューム機構により、**出力形式や話者表示名の変更は
export ステージのみで完了**します。ASR や話者分離は再実行されません。

これを GUI から使えるようにしてください。

- 出力形式の選択を変えて再生成する
- **話者の表示名を設定して再生成する**
  （`SPEAKER_00` → 「田中」のような対応付け）
- 出力先を変えて再生成する

**話者名の設定は「編集」に近い機能ですが、既存の CLI 機能
（`[output].speaker_labels`）を呼び出すだけで実現できます。**
本文の編集とは異なり、コアの変更を伴わないため範囲に含めます。

設定した話者名を保存するかは判断してください。保存する場合、
**会議の参加者名が GUI の設定に残る**点を考慮し、保存場所と扱いを決めてください。

---

## Step 6 — 機密データの扱い

**閲覧機能は、実データを画面に出す最初の機能です。**以下を厳守してください。

- **文字起こし本文を、GUI のログ、設定ファイル、キャッシュに保存しない**
- 検索語を保存しない
- API のレスポンスをブラウザのストレージに永続化しない
- エラー報告に本文を含めない
- **手動確認手順書やテストに、実データの内容を書かない**

テスト用のデータは、**合成または手書きの JSON** を使ってください。
実データから生成したフィクスチャを使わないこと。

## テスト

モデルなしでテストできるものを重点的に書いてください。

- 出力 JSON のパース（正常、`schema_version` 不一致、破損、単語なし）
- 検索とハイライトのロジック（日本語を含む、一致なし、大量一致）
- フィルタのロジック
- 話者表示名の適用
- ジョブ一覧のパースと並び替え
- 再生成時の CLI 引数の組み立て

**テストデータは合成または手書きのものを使ってください。**

GUI の表示は自動テストが困難です。
**`docs/Phase5a_GUI_手動確認手順書.md` に 5b の項目を追加**してください。
特に以下は目視確認が必要です。

- 長時間データでのスクロールの滑らかさ
- 話者色の見やすさ（ダーク・ライト双方）
- 検索ハイライトの視認性
- 日本語フォントの表示

## 実装上の注意

### 作業環境

作業機は NVIDIA GPU 搭載機です。表示性能の確認には実データが必要ですが、
**新規に文字起こしを実行する必要はありません。**既存のジョブがあればそれを使ってください。

必要な場合のみ、`cuda` プロファイルと `large-v3-turbo` で生成してください。
CPU での実行は時間がかかるため避けてください。

### 破壊的変更への配慮

- 既存の CLI の挙動を変えない（`--json` の追加は可）
- 既存のジョブ、出力、設定を無効化しない
- Phase 5a の画面と機能を壊さない

### コミット

- ブランチ `feature/phase5b-gui-viewer`
- Step 単位でコミットする
- `git push` は実行しない
- 実データをコミットしない

---

## 禁止事項

- GUI から `utteran` パッケージを import すること
- 文字起こし本文をログ、設定、キャッシュに保存すること
- 検索語を永続化すること
- 実データから生成したフィクスチャをテストに使うこと
- 全件を DOM に展開すること（仮想スクロールを省くこと）
- 色をコンポーネントに直書きすること
- 実データで性能を確認せずに「完了」と報告すること
- `要件定義.md` を更新せずに仕様を変えること

---

## 不明点があった場合

1. `要件定義.md` と Phase 5a の実装方針を優先する
2. デザインと機能の細部は判断してよい。判断と理由を記録する
3. 判断できない場合、安全側に倒し、記録する
