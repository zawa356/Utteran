## I-1 — 使えないモデルの除去

### 問題

`src/utteran/models/catalog.py` に以下のエントリがあります。

```python
ModelEntry(
    model_id="large-v3-turbo",
    display_name="Whisper large-v3-turbo (OpenVINO)",
    description="将来のIntel向けASR。Phase 2では推論未実装",

    format="OpenVINO IR",
    repository_id="OpenVINO/whisper-large-v3-turbo-fp16-ov",
```

**`openvino` バックエンドは実装されていません。**

この OpenVINO GenAI 経路は結局実装されませんでした。

**取得しても使えない 1.63 GiB を、GUI が選択肢として提示しています。**

### 実施内容

1. このエントリをカタログから**除去する**か、
   **実装されていないことを明示して既定では表示しない**扱いにする
2. 判断と理由を記録する
3. **既にこのモデルを取得してしまった利用者への配慮**を検討する
   （削除を促す案内など。判断してよい）

### あわせて確認すること

**カタログ全体を見直し、「取得できるが使えない」ものが他にないか確認してください。**
バックエンドが実装されているか、前提（ネイティブビルド、IR 生成）が
何かを、各エントリについて確認すること。

## I-2 — GPU で動くかの明示

### 問題

利用者が以下のように誤解しています。

> q5はGPU支援使える、無印はCPU処理になる

**これは正しくありません。**GPU で動くかを決めるのは**バックエンド**です。

| バックエンド | 形式 | Intel 環境での実行 |
|---|---|---|
| faster-whisper | CTranslate2 | **CPU のみ** |
| whisper-cpp | ggml（f16 / q5_0 / q8_0） | **Vulkan / OpenVINO** |

`q5_0` も `f16` も同じ ggml 形式で、どちらも GPU で動きます。
量子化はファイルサイズと速度・精度のトレードオフです。

**この誤解が生じた時点で、UI の表示が不十分です。**

### 実施内容

モデル一覧に、**その環境で GPU が使えるかを表示**してください。

- 「この環境で GPU 実行できる／CPU 実行になる」を明示する
- **検出結果に基づいて判定する**（環境によって変わるため）
- 量子化の意味（サイズと速度・精度の関係）を説明する
- バックエンドと量子化を混同させない表現にする

推奨モデルには、**その環境での推奨理由**を添えてください。
「この環境では最速」「GPU が使えないため低速」など。

## I-3 — Silero VAD を既定で有効にする

### 背景

現在の既定は `vad = false`（opt-in）です。

Phase 3d の対策別測定では、**VAD 単独で以下の効果**が確認されています。

| 条件 | 処理時間 | セグメント | 最大連続反復 |
|---|---:|---:|---:|
| 対策なし | 289.9秒 | 571 | 150 |
| **VAD のみ** | **103.6秒** | 191 | **2** |

**品質と速度の両方に大きく効きます。**既定で有効にすべきです。

### 実施内容

1. **`vad` の既定を `true` に変更する**
2. **Silero VAD モデルを、ウィザードで導入する**
   - ASR モデルと同じ扱いで取得する
   - サイズは小さいはずなので、追加の負担は小さい
3. **モデルが無い場合の挙動を決める**
   - 実行時にエラーとするか
   - 警告のうえ VAD 無効で続行するか
   - **既存の利用者が突然エラーになる事態を避けてください**
4. モデル管理画面でも取得・確認できるようにする
5. **設定で無効にできる状態は維持する**

### 注意

- **既定値の変更により、既存ジョブの `config_hash` が変わります。**
  ASR が再計算されることになりますが、これは仕様どおりです。
  ただし**利用者が驚かないよう、変更点として明記**してください
- whisper.cpp 経路と faster-whisper 経路で、VAD の扱いが異なります
  （`vad` と `vad_filter` が別々に存在します）。
  **両者の関係を整理し、要件定義に記載してください**

## I-4 — モデルの選択肢を広げる

### 問題

カタログに登録されている faster-whisper モデルは以下だけです。

```
large-v3-turbo
large-v3
kotoba-whisper-v2.0
```

**tiny / base / small / medium が登録されていません。**

Phase 3b で「利用者が幅広く選べること」を求めましたが、
ggml 側は動的生成されている一方、faster-whisper 側は large 系に偏っています。

### 実施内容

1. **faster-whisper 側にも小〜中サイズを登録する**
   - tiny / base / small / medium
   - **実際に存在するリポジトリを確認してから登録すること**（推測しない）
2. ggml 側の一覧が適切に生成されているかを確認する
3. **一覧が長くなるため、表示を整理する**
   - 推奨セットを既定表示、全件は明示操作で表示
   - サイズ、速度、精度の傾向が分かる形にする
4. 日本語特化モデル（kotoba-whisper）の位置づけを明示する

**「なぜ large 系しか選べないのか」と利用者が感じた点を解消してください。**
短い音声の試用や、低スペック環境では小さいモデルが有用です。

## I-5 — 取得の進捗表示

### 問題

> 取得ボタンを押してもダウンロード中のフェーズが見えない。
> ページ更新しないと、ダウンロード完了したかどうかがわからない。

**数 GB のダウンロードで進捗が見えないのは、実用上の欠陥です。**

### 実施内容

- 取得中であることを表示する
- **進捗（ダウンロード量、割合、残り時間の目安）を表示する**
- 完了したら自動で一覧を更新する（手動リロードを不要にする）
- 失敗したら理由を表示する
- **キャンセルできる**

進捗の取得方法は判断してよいですが、
既存の SSE の仕組み（ウィザードやジョブで使用）が流用できるはずです。

## I-6 — キュー処理

### 要件

> ダウンロードやOpenVINOの生成などをキューとして扱い、複数の処理をできないか

**モデルの取得、IR 生成、文字起こしをキューで管理してください。**

- 複数の操作を順次実行する
- キューの内容が見える（待機中、実行中、完了、失敗）
- 個別にキャンセルできる
- 並び替えができると望ましい（必須ではない）
- **同時実行は1件**とする（GPU メモリの競合を避けるため）

### 注意

- 既存の「同時実行は1件」の制約（`JobManager`、`SetupWizardService`）と整合させる
- キューの状態を永続化するかを判断する
  （GUI を閉じたら消えるのか、次回に持ち越すのか）
- **文字起こしのジョブとモデル取得を同じキューに入れるか**を判断する
  （別々のキューにする選択肢もあります）

判断と理由を記録してください。

## I-7 — 実行中の設定変更を防ぐ

### 問題

> 文字起こし実行中にも設定値や、文字起こし開始ボタンが押せる

### 実施内容

**I-6 のキューと整合させてください。**

- 「開始」ボタンの挙動を決める

  - 押せなくする（キューがない場合）
- **実行中であることが一目で分かる表示**にする
- 変更が反映されない項目はグレーアウトする

**利用者が「変更したのに反映されない」と誤解しない**ことが目的です。

## I-8 — タスクバーのアイコン

### 問題

> タスクバーのアイコンがPythonのフロッピーのまま。
> アプリ内のアイコンは更新されていそう。

### 原因の候補

**推測で修正せず、確認してください。**

| 仮説 | 確認方法 |
|---|---|
| A. exe にアイコンが埋め込まれていない | `gui.spec` の `icon=` 指定、ビルド後の exe を確認 |
| B. AppUserModelID が設定されていない | pywebview のウィンドウが Python のものとして扱われている |
| C. アイコンキャッシュが残っている | クリーンな環境で確認 |
| D. ビルドし直していない | ビルド日時を確認 |

**B の場合**、Windows では `SetCurrentProcessExplicitAppUserModelID` の
呼び出しが必要になることがあります。

### 実施内容

- 原因を特定して修正する
- **クリーンな環境で確認する**（アイコンキャッシュの影響を排除するため）
- ショートカット、タスクバー、タイトルバー、Alt+Tab のすべてで確認する
