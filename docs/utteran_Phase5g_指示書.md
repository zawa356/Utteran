# utteran — Phase 5g 実装指示（ウィザードの順序見直しと無人実行）

## あなたへの依頼

セットアップウィザードを、**入力を先に済ませて、あとは放置できる**構成に変更してください。
あわせて、プロファイル検証で長時間応答がない問題を調査します。

作業ブランチは `fix/phase5g-wizard-unattended` を新規作成して使用します
（`fix/phase5e-gui-settings` の内容を含む状態から分岐すること）。

---

## 背景

### 現在の流れ

```
welcome → profile選択 → venv構築（10分以上） → model選択 → token入力
       → モデル取得（数GB） → smoke test → 完了
```

**長い待ち時間の後に、2回も利用者の入力を求めています。**

利用者は初回セットアップの間、画面の前に張り付いている必要があります。
venv 構築とモデル取得はいずれも数分から数十分かかるため、
**その間に席を外せる構成にすべきです。**

### あるべき流れ

**入力をすべて先に済ませ、以降を無人で完了させます。**

```
[入力フェーズ — 利用者が操作]
  welcome
  → profile選択
  → 話者分離を使うかの選択
  → HFトークンの入力（話者分離を使う場合）
  → モデルの選択
  → 確認画面（これから何をするか、所要時間とダウンロード量の目安）

[実行フェーズ — 放置可能]
  → venv構築
  → トークンのpreflight（venv構築後に自動実行）
  → モデル取得
  → smoke test
  → 完了
```

---

## 設計上の制約と対処

### トークンの preflight は venv 構築後にしか実行できない

`/api/wizard/token-preflight` は選択プロファイルの CLI を子プロセスとして起動します。
**venv が存在しない入力フェーズでは実行できません。**

したがって検証を2段階に分けてください。

| 時点 | 実施内容 |
|---|---|
| 入力フェーズ | トークンを keyring へ保存し、**保存後の再取得**を確認する |
| venv 構築後 | **preflight を自動実行**（CLI からの解決、gated モデルへのアクセス確認） |

### preflight が失敗した場合

無人実行の途中で失敗するため、**利用者が戻ってきたときに何が起きたか分かる状態**にしてください。

- トークン入力画面へ戻す（汎用エラー画面ではなく）
- 失敗の理由を区別して表示する
  （トークン未解決 / トークン無効 / 利用条件未同意 / ネットワークエラー）
- **既にダウンロード済みのものを無駄にしない**
  （ASR モデルの取得が終わっていれば、それは保持する）
- 修正して再開できる

### 順序の工夫

**pyannote モデルの取得は、ASR モデルより先に試みることを検討してください。**

現在は ASR モデル（1.5GB）→ pyannote（数百MB）の順です。
トークンの問題は pyannote でしか起きないため、**先に pyannote を試せば、
失敗が早く分かります。**大きなダウンロードを終えてから失敗するより良い体験です。

ただし、preflight が正しく機能すれば取得前に検出できるはずです。
どちらの設計を採るか判断し、理由を記録してください。

## 実装内容

### 1. ステップの再構成

上記の流れに沿ってウィザードを組み替えてください。細部は判断して構いませんが、
以下を満たすこと。

- **入力フェーズと実行フェーズが明確に分かれている**
- 実行フェーズに入る前に、確認画面で以下を示す
  - これから実行する内容
  - **おおよその所要時間**
  - **ダウンロード量の目安**
  - 席を外して構わないこと
- 実行フェーズでは、進捗が分かる表示を維持する
- 実行フェーズの各段階が完了するたびに状態を永続化する
  （途中で GUI を閉じても、次回に続きから再開できるように）

### 2. 話者分離の選択

現在はモデル選択画面のチェックボックスです。**独立したステップにしてください。**

- 話者分離は utteran の中心機能であり、既定は「使う」とする
- 使う場合に何が必要か（HF アカウント、**利用条件への同意**、トークン）を示す
- 使わない場合に何が得られないか（誰が話したかが出力されない）を示す
- **後から有効にできる**ことを伝える

### 3. トークン入力（入力フェーズ）

`fix/phase5e-gui-settings` で実装済みの画面を、入力フェーズへ移してください。

この時点では CLI が使えないため、**保存と再取得の確認まで**を行います。

- アカウント作成、**利用条件への同意**、トークン発行の案内とリンク
- **利用条件への同意はトークンとは別に必要**である点を明示する
  （混同すると「トークンは正しいのに失敗する」状態になります）
- マスク入力
- 保存後の再取得確認
- keyring が利用できない場合、代替手段（環境変数、`.env`）を案内する
- **既に設定済みの場合は入力を求めず、「設定済み」と表示する**
- 「後で行う」を選べる（その場合は話者分離なしで進む）

### 4. preflight の自動実行（実行フェーズ）

venv 構築が完了した直後に、自動で実行してください。

- 成功したらそのまま次へ進む
- 失敗したら停止し、トークン入力画面へ戻す
- **失敗の理由を区別する**
- 修正後、venv 構築をやり直さずに再開できる

### 5. 「後で行う」からの復帰

ウィザードを中断した利用者が、後から続きを実行できるようにしてください。

- 設定画面などから再開できる
- どこまで完了しているかが分かる
- 話者分離を後から有効にする経路も同じ仕組みで扱えると望ましい

## 調査項目 — プロファイル検証の長時間応答なし

### 症状

`setup.ps1` の出力が以下で止まり、長時間応答がありません。

```
==> Verifying profile 'intel'
```

### 該当箇所

`setup.ps1` の `intel` プロファイル検証は、重い処理を2つ連続で実行します。

```powershell
$DeviceText = ... utteran devices --json ...
$XpuProbe = ... python -c "import torch; print(torch.xpu.is_available())"
```

**どちらも進捗を出力しません。**`Write-Step` の直後から完了まで無言です。

- torch の XPU 版は初回 import が重い（DLL のロードとデバイス初期化）
- OpenVINO の GPU デバイス列挙は、環境によって時間がかかる場合がある

### 実施内容

1. **実際に何秒かかるかを計測する**
   - `utteran devices --json` 単体
   - `python -c "import torch; print(torch.xpu.is_available())"` 単体
   - 初回と2回目以降の差
2. **本当に停止するのか、時間がかかっているだけかを判定する**
3. 判定に応じて対処する

| 判定 | 対処 |
|---|---|
| 時間がかかっているだけ | **進捗を出す。**何を実行中か、初回は時間がかかる旨を表示する |
| 特定条件で停止する | 原因を特定し、タイムアウトと回避策を実装する |

4. **`devices` と torch のプローブを1回にまとめられないか検討する**
   （`devices --json` が torch XPU の情報を含むなら、別プロセスの起動は不要かもしれません）

5. **GUI 側にも反映する**
   - 実行フェーズで「応答がないように見える」時間を作らない
   - 既存の stalled 検出を活かし、時間がかかっている旨を表示する

## 調査項目 — トークンエラーの再発

### 症状

`fix/phase5e-gui-settings` の内容でも、以下のエラー画面が出るとの報告があります。

```
この手順でエラーが発生しました
設定画面でHugging Faceトークンを保存し、モデル利用条件への同意を確認してください。
```

このメッセージは `i18n.js` の `guide_token` で、**ウィザードのジョブが失敗したとき**に
`wizardShowError()` が出す汎用エラー画面です。トークン入力画面のエラーではありません。

### 実施内容

**どの状況で出ているのかを特定してください。**

| 仮説 | 確認方法 |
|---|---|
| A. 古いビルドを実行している | 実行中の exe のビルド日時、バージョンを確認 |
| B. preflight を通過したが、モデル取得で失敗している | ウィザードのジョブログを確認 |
| C. preflight が実行されない経路がある | 話者分離オフで進んだ場合の挙動を確認 |
| D. smoke test で失敗している | ジョブの種別を確認 |

**推測で修正しないでください。**配布版で再現させ、原因を特定してから対処すること。

### 対処方針

原因にかかわらず、**トークン関連の失敗は汎用エラー画面へ飛ばさないでください。**
トークン入力画面に留め、その場で修正できるようにします。

`guide_token` / `guide_license` が返ってきた場合は、
トークン入力画面へ戻す経路を用意してください。

## 実装上の注意

### 機密データ

- トークンをログ、API レスポンス、画面に出さない
- デバッグ用の出力を残さない
- 実データを検証に使わない
- スクリーンショットに他のウィンドウが写り込まないよう注意する

### 破壊的変更への配慮

- 既存の venv、モデル、設定、ジョブを壊さない
- 既にセットアップ済みの利用者にウィザードを再表示しない
- `fix/phase5e-gui-settings` で実装した内容を壊さない
  （トークン画面、preflight API、`config token-status`、状態の永続化）

### コミット

- ブランチ `fix/phase5g-wizard-unattended`
- 作業単位でコミットする
- `git push` は実行しない
- ビルド成果物をコミットしない

---

## 禁止事項

- 配布版で確認せずに「修正した」と報告すること
- 原因を特定せずに修正から入ること
- 実行フェーズの途中で利用者の入力を求めること
- トークン関連の失敗を汎用エラー画面へ飛ばすこと
- 進捗を出さない長時間処理を残すこと
- 既存の環境を壊すこと
- `要件定義.md` を更新せずに仕様を変えること

---

## 不明点があった場合

1. `要件定義.md` と `fix/phase5e-gui-settings` の方針を優先する
2. ウィザードの構成の細部は判断してよい。判断と理由を記録する
3. 判断できない場合、安全側に倒し、記録する
