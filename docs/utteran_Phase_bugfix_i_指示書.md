## 緊急度

**高い。**

**0.1.22 以降の利用者は、アンインストールに失敗します。**
配布済みの版すべてが影響を受ける可能性があります。

**他の作業より優先してください。**

---

## 症状

0.1.23 のアンインストール中に、以下のダイアログが表示されて中断します。

```
Runtime error (at 31:89):
内部エラー: Unknown constant "userprofile"
```

**アンインストールが完了しません。**

---

## 原因（推定・確認すること）

**Inno Setup に `{userprofile}` という定数は存在しません。**

環境変数の `%USERPROFILE%` と混同したものと推定されます。

Inno Setup で同等の場所を指すには、以下のいずれかを使います。

| 書き方 | 意味 |
|---|---|
| `{%USERPROFILE}` | 環境変数を参照する記法（`%` が波括弧の内側） |
| `{localappdata}` | `%LOCALAPPDATA%` |
| `{userappdata}` | `%APPDATA%` |
| `{userdocs}` | ドキュメントフォルダ |

**用途に応じて適切な定数を選んでください。**環境変数参照より、専用の定数のほうが安全です。

**推定で修正しないでください。**該当箇所を特定し、何を指したかったのかを確認してから直します。

### 発生箇所

**エラーメッセージの `31:89` は、行 31・桁 89 を指します。**
アンインストール時に評価される箇所です。

---

## なぜ検出されなかったか（重要）

**Inno Setup の定数エラーは、コンパイル時には検出されません。**
**その行が実行されて初めて発生します。**

`ユーザー確認事項.md` の **A-1（クリーンインストール後のアンインストール）が、
まさにこれを検出するための項目でした。**実機確認を後回しにしたため、
**0.1.22 から 0.1.26 まで残りました。**

**この経緯を `AISTATE.md` へ記録してください。**

さらに重要な点があります。**ac-2（0.1.22）の作業では、隔離環境で 0.1.21 の
clean install と silent uninstall を実施し、残留を確認しています。**

**つまりハーネスは存在します。**0.1.22 以降で再実行されていれば検出できたはずです。
**なぜ再実行されなかったかを確認し、記録してください。**

- 正しい定数へ置き換える

## Step 3 — すべての定数の検証（本作業の要）

**`{userprofile}` だけを直して終わらせないでください。**

同種の誤りは実行時にしか現れないため、**他にも存在する可能性があります。**

### 作業

- **`.iss` ファイル内のすべての定数を洗い出す**
- Inno Setup が実際に定義している定数と照合する
- `[Code]` セクション内で組み立てられる定数も対象に含める
- **install 時に評価されるものと、uninstall 時に評価されるものを区別する**

**uninstall 側は実行機会が少ないため、誤りが残りやすい。**

### 記録すること

- 検証した定数の一覧
- 誤りが他にもあった場合、その内容

---

## Step 4 — 検出の仕組み（再発防止）

**実行時にしか出ないエラーを、実行時にしか検出できない状態のまま残さないでください。**

### 求めるもの

**ビルド時またはテスト時に、定数の妥当性を検証する仕組み。**

方向としては次が考えられます。**実現方法は判断に任せます。**

- `.iss` を解析し、使用されている定数を既知の一覧と照合する検査
- **`{%...}` 形式や `{code:...}` 形式を正しく区別すること**
- 未知の定数があればビルドを失敗させる

### 前例

**ac-3 で、バージョンの不整合を検出するテストを追加した前例があります。**
package / GUI / README の一致を検証し、更新漏れがあれば失敗します。

**同じ考え方をここへ適用してください。**

### 実現できない場合

**理由を記録し、代替として `ユーザー確認事項.md` の A-1 を
「版を上げるたびに実施する」項目へ格上げしてください。**

## Step 5 — 隔離環境での検証

**ac-2 で使用したハーネスを再実行してください。**

- 隔離環境へ clean install する
- プロファイルとモデルを作る
- GUI を起動して終了する（ログとキャッシュを生成させる）
- **silent uninstall と対話 uninstall の両方を実施する**
- **エラーなく完了することを確認する**
- 残留を確認する

**開発環境の実データを危険にさらさないこと。**
ac-2 と同じく、隔離した場所で実施してください。

### 上書きインストールでの復旧確認

**既に壊れた版が入っている利用者への復旧手段を確認してください。**

Inno Setup は上書きインストール時に `unins000.exe` / `unins000.dat` を
置き換えるため、**修正版を上書きすればアンインストーラーが差し替わる**はずです。

- 0.1.26（壊れた版）を隔離環境へ入れる
- **修正版を上書きインストールする**
- **アンインストールが正常に完了することを確認する**

**これが確認できれば、利用者へ案内できます。**

## 不明点があった場合

1. `要件定義.md` と ac-2 の実装を優先する
2. 判断できない場合、**安全側に倒し、記録する**
3. **削除の可否に迷う場合、消さない側に倒す**
4. **定数の妥当性が判断できない場合、使用を避ける**
   （動くか分からない定数を残すより、確実なものを使う）
