# utteran — Phase 5c 実装指示（初回セットアップウィザード）

## あなたへの依頼

Phase 5c として、**GUI による初回セットアップウィザード**を実装してください。

導入のハードルを下げることが目的です。利用者が「プロファイル」という内部概念を
理解しなくても、自分の環境に適した構成を選べる状態にします。

着手前に必ず以下を読んでください。

1. `AISTATE.md`
2. `要件定義.md`（特に GUI と実行環境分離の章）
3. `README.md`
4. `setup.ps1` の実装

作業ブランチは `feature/phase5c-setup-wizard` を使用します（作成済み）。

---

## 背景: 解決すべき2つの課題

### 課題1 — uv の導入が手動

現在の `setup.ps1` は uv の存在を確認し、未導入なら案内を表示して終了します。
利用者は自分で uv を導入してから、もう一度実行する必要があります。

### 課題2 — プロファイルの選択基準が分からない

現在の README のプロファイル表は以下です。

| Profile | 用途 |
|---|---|
| `intel` | Intel Arc/NPU |
| `vulkan` | AMD等 |

**「用途」がハードウェア名になっているだけで、選択の基準になっていません。**

Intel の CPU を使っていて GPU がない人は、`intel` と `cpu` のどちらを選ぶべきか
判断できません。`vulkan` の「AMD等」の「等」も曖昧です。

実際の違いは以下ですが、これが表からは読み取れません。

| | intel | vulkan |
|---|---|---|
| ASR の高速化 | OpenVINO と Vulkan の両方 | Vulkan のみ |
| **話者分離の高速化** | **あり（XPU）** | なし（CPU 実行） |
| OpenVINO IR 変換 | 必要（OpenVINO 構成使用時） | 不要 |

**話者分離が GPU で動くかどうかが最大の差**なのに、そこが書かれていません。

### 解決方針

**プロファイル名を利用者に選ばせるのをやめます。**

GUI がハードウェアを検出し、推奨構成を提示する形にします。利用者は
「推奨で進む」か「別を選ぶ」かだけを判断すれば済みます。

## Phase 5c の実装範囲

### 含むもの

- 初回起動の判定とウィザードの起動
- ハードウェア検出と推奨構成の提示
- uv の自動導入
- プロファイル venv の構築（進捗表示付き）
- ffmpeg の確認と導入
- モデルの取得
- Hugging Face トークンの設定
- 完了確認と動作テスト
- 後からウィザードを再実行する手段

### 含まないもの

- インストーラー化（5d）
- `setup.ps1` の対話化
  （**`setup.ps1` は自動化向けとして現状の引数指定を維持してください**）

## Step 0 — 検証方法の設計

**この作業には構造的な困難があります。**

作業機（Intel 機）には既に uv、`intel` プロファイル、モデル、ffmpeg が
揃っています。**「何も無い状態から導入する」経路を、そのままでは検証できません。**

着手前に検証方法を設計し、`AISTATE.md` に記録してください。

検討すべき観点:

- 既存環境を壊さずに「未導入」を再現する方法
  （別のディレクトリへ clone する、環境変数で参照先を変える、
  検出結果を注入するなど）
- 実際に venv を作る場合、既存の `.venvs` に影響しない配置
- uv の導入を試す場合、既存の uv を壊さない方法
- 検証後に環境を元に戻す手順

**既存環境を壊す検証は行わないでください。**
実機で検証できない部分は、検出結果を注入したテストで代替し、
「実機未検証」として明記してください。

## Step 1 — 初回起動の判定

### 判定基準

以下のいずれかを満たす場合、ウィザードを起動します。

- プロファイル venv が1つも存在しない
- GUI の設定ファイルが存在しない、またはセットアップ完了の記録がない

**判定は慎重に行ってください。**既に使えている利用者に対して毎回
ウィザードが出るのは煩わしく、逆に必要な人に出ないと導入できません。

### 再実行の手段

- 設定画面などから、いつでもウィザードを開けるようにする
- プロファイルを追加したい場合にも使える
  （例: Intel 機で `intel` を使っていた人が `vulkan` も試したくなった場合）

### 中断と再開

- 各ステップの完了状態を記録し、中断後に続きから再開できるようにする
- 途中で閉じても、次回起動時に再開を提案する

---

## Step 2 — ハードウェア検出と推奨

### 検出

`utteran devices --json` を使いたいところですが、**プロファイル venv が
存在しない時点では実行できません。**

以下を検討し、方針を決めてください。

- GUI 環境だけで実行できる最小限の検出を実装する
  （GPU の存在、ベンダー、システム RAM など）
- あるいは、まず最小構成の venv を作り、そこで `devices` を実行する
- 判断と理由を記録してください

**GUI 環境に推論系の依存を追加しないでください。**
検出のために torch や openvino を入れることは禁止します。

### 推奨の提示

検出結果から推奨プロファイルを決め、**理由とともに提示**してください。

推奨の考え方:

| 検出結果 | 推奨 | 理由の例 |
|---|---|---|
| NVIDIA GPU | `cuda` | ASR と話者分離の両方が GPU で動作 |
| Intel GPU (Arc/iGPU) | `intel` | ASR は OpenVINO/Vulkan、話者分離は XPU で動作 |
| AMD その他の GPU | `vulkan` | ASR が Vulkan で動作、話者分離は CPU |
| GPU なし | `cpu` | CPU で動作。処理時間は長くなります |

**表示すべき内容:**

- 検出されたハードウェア
- 推奨されるプロファイルと、**その構成で何が高速化されるか**
- **話者分離が GPU で動くかどうか**（最も重要な差）
- 追加で必要になる作業（OpenVINO IR 変換、Vulkan SDK など）
- おおよそのディスク使用量

**プロファイル名を前面に出さないでください。**
「あなたの環境では、文字起こしと話者分離の両方を GPU で実行できます」のような、
**利用者にとっての意味**を主として提示してください。
プロファイル名は補足情報として示す程度にします。

### 別の選択肢

推奨以外も選べるようにしますが、**選べない構成は提示しない**でください。
NVIDIA GPU がない環境で `cuda` を選択肢に出さないこと。

選択肢を出す場合、それぞれの利点と制約を併記してください。

## Step 3 — uv の自動導入

### 方針

utteran は ffmpeg の取得時に SHA-256 検証を行っています。
**uv も同じ基準で扱ってください。**

`irm https://astral.sh/uv/install.ps1 | iex` は公式の推奨手順ですが、
**ダウンロードしたスクリプトを検証せず実行する**形です。ffmpeg だけ検証して
uv は無検証というのは一貫しません。

以下を調査し、方針を決めてください。

- GitHub のリリースアセットを直接取得し、チェックサムを検証する方法
- 公式インストールスクリプトを使う場合の検証手段
- どちらを採用するか、判断と理由を記録する

### 必須要件

- **導入前に、何をするかを表示して確認を求める**
  （利用者の同意なく外部からバイナリを取得しない。
  Phase 2 以来のモデル暗黙ダウンロード禁止と同じ方針です）
- 導入先はユーザー領域（管理者権限を要求しない）
- **既に uv が導入されている場合は何もしない**
- バージョンを確認し、古すぎる場合の扱いを決める
- 導入に失敗した場合、手動導入の手順を案内する
- ネットワークに接続できない場合の案内

### Linux

Linux は副対象です。**対応するかどうかを判断し、記録してください。**
対応しない場合、Linux では手動導入を案内する形で構いません。

## Step 4 — 環境の構築

### 実行内容

1. uv の確認・導入（Step 3）
2. 選択されたプロファイルの venv 構築
3. ffmpeg の確認・導入
4. モデルの取得
5. Hugging Face トークンの設定（話者分離を使う場合）
6. 動作確認

### 進捗表示

**venv の構築は数分から十数分かかります。**（CUDA プロファイルは torch だけで
約 2.4 GB、Intel プロファイルは 5.3 GB）

- **何をしているかを具体的に表示する**（「準備中...」だけにしない）
- 進捗が分かる形にする。無反応に見える時間を作らない
- ダウンロード量が大きい場合は事前に伝える
- 中断できるようにする

`setup.ps1` を呼び出すか、`uv` を直接呼ぶかは判断してください。
`setup.ps1` を使う場合、その出力をパースして進捗にする必要があります。

### ffmpeg

`setup.ps1` に既に取得処理があります（gyan.dev の release essentials、
SHA-256 検証付き）。これを再利用するか、GUI から独立して呼ぶかを判断してください。

**GPLv3 である旨の表示**を省略しないでください。

### モデルの取得

- 推奨モデル（`large-v3-turbo`）を既定として提示する
- サイズと所要時間を事前に表示する
- 話者分離を使うかを確認し、使う場合は community-1 も取得する
- **利用者が「後で」を選べるようにする**（必須にしない）

### Hugging Face トークン

- 話者分離を使う場合のみ案内する
- **モデル利用条件への同意が必要**である旨を明示し、ページへのリンクを示す
- トークンの取得手順を案内する
- 入力されたトークンは **OS キーリングにのみ保存**する
- **入力後、実際に取得できるかを確認する**
  （トークンが有効でも、利用条件に同意していないと失敗します。
  この2つを区別してエラーを出すこと。Phase 1 で実装済みの分類を使う）

---

## Step 5 — 完了確認

セットアップの最後に、**実際に動作するかを確認**してください。

- 短い音声（合成でよい）で文字起こしを実行する
- 話者分離を設定した場合は、それも含めて確認する
- 成功したら、その旨と次の操作（実際のファイルを処理する）へ導く
- 失敗したら、原因と対処を示す

**「セットアップが完了しました」とだけ表示して終わらないでください。**
実際に動くことを確認できていない状態で完了とするのは不誠実です。

確認用の音声は、**実データを使わない**でください。合成音声を生成するか、
無音に近い短い音声で構いません（文字起こし結果の内容は問いません）。

## 実装上の注意

### 作業環境

**作業機は Intel 機です。**

- `intel` プロファイルは構築済みのはずです
- `cuda` プロファイルはこの機では検証できません
- uv、ffmpeg、モデルも導入済みのはずです
- したがって Step 0 の検証設計が重要になります

### 機密データ

- トークンをログ、API レスポンス、画面に出さない
- 動作確認に実データを使わない
- `.env` を読み取らない

### 破壊的変更への配慮

- **既存の venv、モデル、設定を壊さない**
- `setup.ps1` の引数指定を変更しない（追加は可）
- Phase 5a・5b の画面と機能を壊さない

### コミット

- ブランチ `feature/phase5c-setup-wizard`
- Step 単位でコミットする
- `git push` は実行しない
- 実データをコミットしない

---

## 禁止事項

- 既存の環境（venv、uv、モデル、ffmpeg）を壊す検証を行うこと
- GUI 環境に推論系の依存を追加すること
- GUI から `utteran` パッケージを import すること
- 利用者の同意なく外部からバイナリを取得すること
- uv を検証なしで取得・実行すること
- プロファイル名を理解させる前提の UI にすること
- 選択できない構成を提示すること
- 動作確認せずに「セットアップ完了」と表示すること
- トークンを `config.toml` に書く、画面に表示する、ログに出すこと
- 実機未検証の項目を「検証済み」と報告すること
- `要件定義.md` を更新せずに仕様を変えること

---

## 不明点があった場合

1. `要件定義.md` と既存の `setup.ps1` の方針を優先する
2. UI とウィザードの流れは判断してよい。判断と理由を記録する
3. 判断できない場合、安全側に倒し、記録する
4. 設計の変更を伴う判断は、実装前に `要件定義.md` へ反映する
