## Phase 3a の調査結果のうち、本フェーズの前提となるもの

以下は Phase 3a で実機確認済みの事実です。設計はこれを前提としています。

- whisper.cpp は **v1.9.1** を採用済み。CPU / OpenVINO / Vulkan / OpenVINO+Vulkan の
  全構成でビルドと実推論に成功している
- `--dtw` のプリセットに **`large.v3.turbo` が存在する**
- **`whisper-cli` は flash attention が既定で有効であり、`--dtw` を指定しても
  無言で DTW を無効化する。`--no-flash-attn`（`-nfa`）の併用が必須**
- `-ojf` の JSON は、各 segment が `tokens[]` を持ち、各 token が
  `text, timestamps, offsets, id, p, t_dtw` を持つ。特殊トークンの `t_dtw` は常に `-1`
- 日本語のトークンは 1 文字未満の UTF-8 バイト断片になることがあり、
  `whisper-cli` 自身はトークンを単語へ統合しない
- Vulkan ビルドには Vulkan SDK 同梱の `glslc` が必須

**未確認のまま残っている事項**（本フェーズで確認すること）:

- large-v3-turbo の実 ggml モデルで `--dtw large.v3.turbo` が正常動作するか
- `t_dtw` の単位（ミリ秒か、10ミリ秒単位か）

## Step 1 — 単語レベルタイムスタンプの設計

**本フェーズで最も重要な部分です。** ここの品質が話者分離の精度に直結します。

### 適用条件

`--no-flash-attn` を付けると推論速度が落ちるため、常時適用はしません。

```toml
[asr]
word_timestamps = "auto"   # auto | always | never
```

- `auto`（既定）: **話者分離が有効なときのみ**単語タイムスタンプを取得する
- `always`: 常に取得する
- `never`: 取得しない（`Segment.words` は空になる）

`align.py` は単語がない場合にセグメント単位の割当へフォールバックする必要があります。
現在の実装がこれに対応していない場合、フォールバック経路を追加してください。
既存の faster-whisper 経路の挙動は変えないこと。

### whisper-cli の引数

単語タイムスタンプを取得する場合:

```
--dtw <preset> --no-flash-attn --output-json --output-json-full
```

`<preset>` はモデルから決定します。カタログにモデルごとの DTW プリセットを持たせ、
`[asr.whisper_cpp].dtw = "auto"` のとき自動解決してください。
プリセットが存在しないモデルを単語タイムスタンプ付きで使おうとした場合、
明確なエラーを出すか、警告のうえ単語なしで続行するかを決め、要件定義に記載してください。

**`--dtw` を指定したあと、実際に DTW が有効になったことを検証してください。**
Phase 3a の調査によれば、無効化されても警告ログが出るだけでエラーになりません。
`t_dtw` が全トークンで `-1` の場合は、単語タイムスタンプの取得に失敗したものとして
扱い、警告を出してください。黙って壊れた時刻を返さないこと。

### トークンから単語への変換

`-sow` と `--max-len` は使わないでください。これらはセグメント構造そのものを
単語単位に変えてしまい、whisper 本来の文単位のセグメントが失われます。

代わりに、**whisper のセグメント構造は維持したまま、各セグメント内のトークンを
Python 側で単語へ統合**してください。

変換規則:

1. 特殊トークンを除外する（`[_BEG_]`、`<|...|>` など。テキストが `[` や `<|` で始まるもの）
2. **UTF-8 のバイト断片を結合し、正しい文字列になるまで連結する**
   （日本語では 1 トークンが 1 文字未満になるため、これを行わないと文字化けする）
3. 単語の境界を決める
   - 空白で区切られる言語: 先頭が空白のトークンで新しい単語を開始する
   - 日本語・中国語など: 文字単位を基本とし、直後の句読点は直前の単語へ含める
4. 各単語の `start` / `end` を、構成トークンの `t_dtw` から決定する
5. `t_dtw` が `-1` のトークンは、`offsets` の値でフォールバックする
6. 単語の `probability` は、構成トークンの `p` の平均とする

**`t_dtw` の単位を必ず実測で確認し、秒への変換を正しく行ってください。**
`offsets` はミリ秒整数であることが確認済みですが、`t_dtw` は別系統の値です。
変換後の単語時刻が、所属するセグメントの時刻範囲内に収まることを検証してください。

### 粒度が `align.py` に与える影響

日本語では単語が文字単位に近い粒度になるため、単語数が faster-whisper より
多くなる可能性があります。`align.py` の「2 単語未満のセグメントは吸収する」という
閾値の挙動が変わります。

以下を実施してください。

1. 同一音声を faster-whisper と whisper-cpp の双方で処理し、単語数を比較する
2. 閾値の既定値をバックエンドごとに変える必要があるかを判断する
3. 必要なら `[alignment]` に設定を追加し、要件定義へ反映する

## Step 2 — モデルカタログの拡張

ggml モデルは Hugging Face の whisper.cpp 配布リポジトリから取得します。

### 要件

- **利用者が幅広く選べること**を優先します
- サイズ（tiny / base / small / medium / large-v1 / large-v2 / large-v3 / large-v3-turbo）と
  量子化（f16 / q5_0 / q5_1 / q8_0 など）の組み合わせを登録する
- **実際にリポジトリに存在するファイル名を確認してから登録してください。**
  推測でファイル名を書かないこと
- 英語専用の `.en` 系は既定の一覧から除外し、`--all` 指定時のみ表示する
- 各エントリに、モデルサイズ、量子化、DTW プリセット、概算ファイルサイズ、
  ライセンスを持たせる
- 一覧が長くなるため、`models list --available` は**推奨セットのみを既定表示**し、
  `--all` で全件を表示する構成にする

推奨セットの案（変更してよい。判断を記録すること）:

```
whisper-cpp:large-v3-turbo         f16、既定候補
whisper-cpp:large-v3-turbo-q5_0    軽量、iGPU 向け
whisper-cpp:large-v3               精度優先
whisper-cpp:large-v3-q5_0
whisper-cpp:medium-q5_0
whisper-cpp:base                   動作確認用
```

### 量子化と OpenVINO の関係

**OpenVINO エンコーダ IR はエンコーダを完全に置き換えるため、
ggml 側の量子化はデコーダにのみ影響します。**

つまり「q5_0 の軽量 ggml + OpenVINO エンコーダ IR」という組み合わせが成立し、
iGPU 環境では有力な選択肢になります。IR はモデルサイズ単位で 1 つあれば足り、
量子化ごとに変換する必要はありません。

ただし whisper.cpp は IR のパスを ggml ファイル名から導出するため、
**同じ IR を量子化違いのファイル名でも参照できるようにする仕組みが必要です。**
（コピー、ハードリンク、または whisper-cli の引数で IR パスを明示する）
whisper.cpp v1.9.1 が IR パスの明示指定に対応しているかを確認し、
対応していればそれを使ってください。

## Step 3 — OpenVINO エンコーダ IR の変換

```
utteran models prepare-openvino <モデルID> [--device GPU] [--purge-cache]
utteran models list-openvino
utteran models remove-openvino <モデルID>
```

### 要件

- `[openvino]` extras（`openai-whisper`、`onnxscript`、`openvino`）が必要
- 未導入の場合、必要な extras と `setup.ps1` の実行を案内するエラーを出す
- **変換には OpenAI 公式の PyTorch 重みが別途必要**（large-v3 なら約 3GB）。
  ggml ファイルとは別のダウンロードが発生する旨を、実行前に表示して確認を求める
  （`--yes` で省略可）
- 変換後、PyTorch 重みのキャッシュは不要になるため `--purge-cache` で削除できるようにする
- 生成物の配置場所と命名は、whisper.cpp が期待する規約に従う。
  **実際の whisper.cpp v1.9.1 のソースを読んで確認してください**
- 変換済み IR の一覧と削除ができること
- `models verify` で IR の存在と整合性も検証すること

### 参考実装について

`_tmp/` の参考実装は、upstream の変換スクリプトのバグを 2 箇所修正したものを
vendor 同梱しています。**その修正内容を確認し、v1.9.1 の変換スクリプトで
同じ問題が残っているかを検証してください。**

- 既に修正されている場合、upstream のスクリプトをそのまま使う
- 残っている場合、修正版を vendor 同梱し、修正内容と理由を明記する
- いずれの場合も、判断を `AISTATE.md` に記録する

## Step 4 — `whisper-cpp` ASR バックエンド

`src/utteran/asr/whisper_cpp.py` を実装します。

### インターフェースの整合

既存の `ASRBackend` 抽象基底に従いますが、サブプロセス実行のため意味が変わります。

| メソッド | 実装内容 |
|---|---|
| `is_available()` | ネイティブビルドの manifest が存在し、実行可能な構成が 1 つ以上ある |
| `available_devices()` | Vulkan デバイス、OpenVINO デバイス、CPU |
| `load()` | 実行ファイルとモデルの解決・検証のみ。モデルは常駐しない |
| `transcribe()` | `whisper-cli` をサブプロセスで実行し、JSON を読んで共通型へ変換 |
| `unload()` | 一時ファイルの後始末 |

**バッチ処理でモデルが常駐しなくなります。**Phase 2 で実装した
「バッチ全体でモデルを 1 度だけロード」が whisper-cpp では効きません。
ファイルごとにモデルのロードが発生することを README に明記してください。
`BackendPool` がこの前提で壊れないことも確認してください。

### 実行時の要点

- 実行ファイルは Phase 3a の manifest から構成名で解決する
- **OpenVINO の DLL ディレクトリは、実行時に現在の venv から動的に解決する**
  （manifest に焼き込まない方針は Phase 3a で確立済み）
- 出力 JSON は一時ディレクトリに書かせ、読み取り後に削除する
  （ジョブディレクトリを直接汚さない）
- 進捗は `--print-progress` の標準エラー出力をパースして通知する
- キャンセルはプロセスツリーの終了で行う。
  Phase 2 の受入試験で解決した Windows 固有の問題（U-002）と同じ手法を使うこと
- 標準エラー出力をそのままユーザーに見せない。秘密値のマスクを通すこと
- 入力は Phase 1 で正規化済みの 16kHz mono WAV を渡す

### 主な引数の対応

| 設定 | whisper-cli 引数 |
|---|---|
| モデル | `-m <ggml path>` |
| 言語 | `-l <code>`（auto の場合の指定方法を確認すること） |
| スレッド数 | `-t <n>`（0 なら自動決定） |
| ビームサイズ | `-bs <n>` |
| OpenVINO デバイス | エンコーダのデバイス指定（実際のオプション名を確認すること） |
| Vulkan デバイス | デバイス番号の指定（実際のオプション名を確認すること） |
| 単語タイムスタンプ | `--dtw <preset> --no-flash-attn` |
| 出力 | `--output-json --output-json-full --output-file <prefix>` |

**引数名は推測せず、`whisper-cli --help` と v1.9.1 のソースで確認してください。**

## Step 5 — 自動選択とフォールバック

### auto の優先順位

```
1. CUDA が利用可能              → faster-whisper / cuda
2. Vulkan + OpenVINO GPU        → whisper-cpp / openvino_vulkan
3. Vulkan のみ                  → whisper-cpp / vulkan
4. OpenVINO GPU のみ            → whisper-cpp / openvino
5. いずれもなし                 → faster-whisper / cpu
```

**CPU フォールバックは faster-whisper のままにしてください。**
参考実装の実測では whisper.cpp の CPU 構成は 60 秒音声に 144 秒かかっており、
CTranslate2 の int8 より明らかに遅いためです。

自動選択の結果と、その理由を情報として表示してください。

### フォールバック

GPU の初期化に失敗した場合、`variant = auto` のときのみ次の構成へ退避します。

- 標準エラー出力のパターンから初期化失敗を検出する
  （参考実装が使っているパターンが参考になるが、v1.9.1 で同じ文言かを確認すること）
- 退避した事実と理由を必ず表示・記録する
- **明示的に構成を指定された場合は退避せず、エラーとする**
  （Phase 1 以来の方針を維持する）
- 退避は 1 回だけとし、無限に降りていかないこと

## 実装上の注意

### 参考実装の扱い

`_tmp/` の TranscriptTool は設計の参考にしてください。
**コードをそのままコピーせず、utteran の構造に合わせて実装してください。**

特に以下は utteran では方針が異なります。

- 単語レベルタイムスタンプ（参考実装は非対応）
- OpenVINO DLL パスの解決（参考実装は manifest へ焼き込み、utteran は動的解決）
- セグメント単位の話者割当（参考実装の方式は使わない）

### 破壊的変更への配慮
