# utteran — Phase 5d 実装指示（インストーラー化）

## あなたへの依頼

Phase 5d として、**Windows 向けインストーラーの作成**を実装してください。

Python も uv も知らない利用者が、インストーラーを実行するだけで
utteran を使い始められる状態にすることが目的です。

着手前に必ず以下を読んでください。

1. `AISTATE.md`
2. `docs/Phase5d事前準備.md`（**特に「5d へ向けた申し送り事項」**）
3. `要件定義.md`
4. `docs/リリース手順.md`

作業ブランチは `feature/phase5d-installer` を使用します（作成済み）。

---

## 決定済みの方針

| 項目 | 決定 |
|---|---|
| uv の同梱 | **同梱しない。**初回セットアップ時に取得する（Phase 5c で実装済み） |
| 実行ファイルの署名 | **行わない。**ただし後から差し込める構造にする |
| SmartScreen 対策 | 警告の回避手順を案内し、SHA-256 を公開する |
| アンインストール | **削除対象を利用者に選択させる** |

### 署名について

自己署名証明書は検討されましたが、**SmartScreen の警告は回避できません。**
評価は発行元の実績に基づくため、自己署名では実績が積まれないためです。
利用者が証明書を信頼済みルートに手動登録した場合のみ「発行元: 不明」が改善しますが、
その手間に見合いません。

したがって未署名とし、**改ざん検知は SHA-256 の公開で担保**します。
将来 Azure Trusted Signing 等を採用する場合に備え、
ビルド手順に署名ステップを差し込める構造にしておいてください。

**この判断と理由を `要件定義.md` に記録してください。**

## 配布物の構成

```
インストーラー（数十 MB 程度）
├── GUI 本体（PyInstaller で固めた実行ファイル）
│   └── Python ランタイム、FastAPI、pywebview を含む
├── ショートカット、レジストリ登録
└── アンインストーラー
        ↓ 初回起動時（Phase 5c のウィザード）
    uv の取得 → プロファイル venv の構築 → モデル取得 → 動作確認
```

**プロファイル venv をインストーラーに含めないでください。**
CUDA で約 2.4 GB、Intel で 5.3 GB あり、配布物として非現実的です。

## Step 1 — PyInstaller による GUI のパッケージ化

### 対象

`src/utteran_gui` とその依存のみです。

**`utteran` パッケージ（推論コア）を含めないでください。**
Phase 5a 以来の原則であり、含めると配布サイズが数 GB になります。

### 確認すべき点

- **pywebview が正しく動作するか**
  WebView2 ランタイムへの依存があります。Windows 11 は標準搭載ですが、
  Windows 10 では未導入の場合があります。**検出と案内が必要かを判断してください**
- **Web アセット（HTML/CSS/JS）が同梱されるか**
  PyInstaller はデータファイルを自動では含めません。明示的な指定が要ります
- **uvicorn の動的インポートが解決されるか**
  hidden imports の指定が必要になる可能性があります
- **起動時間**
  onefile 形式は起動のたびに展開が走り、数秒かかります。
  onedir 形式のほうが速いですが、ファイル数が増えます。
  **どちらを採るか判断し、理由を記録してください**

### 動作確認

**ビルドした実行ファイルを、開発環境の外で実行してください。**

- 開発用の venv が有効でない状態
- リポジトリのディレクトリ外
- 可能なら、Python が入っていない環境

ここで動かなければ配布物として意味がありません。

## Step 2 — Inno Setup によるインストーラー

### 基本要件

- **管理者権限を要求しない**（ユーザー領域へインストール）
- インストール先を選択できる
- スタートメニューとデスクトップにショートカットを作る（後者は任意選択）
- アンインストーラーを登録する
- **日本語と英語に対応する**

### インストール時の表示

以下を明示してください。

- **初回起動時に追加のダウンロードが発生すること**
  （uv、プロファイル venv、モデルで合計数 GB）
- ネットワーク接続が必要であること
- 必要なディスク容量の目安

**これを伝えずにインストールさせると、初回起動で利用者が驚きます。**

### ライセンス表示

- MIT ライセンスを表示する
- **依存物のライセンスが異なる旨を明示する**
  （特に ffmpeg は GPLv3、pyannote モデルは利用条件への同意が必要）
- `THIRD_PARTY_NOTICES.md` を配布物に含める

### アンインストール

**削除対象を利用者に選択させてください。**

| 対象 | 場所 | 既定 |
|---|---|---|
| アプリ本体 | インストール先 | 常に削除 |
| GUI 設定 | `platformdirs` 配下 | 選択 |
| プロファイル venv | `.venvs`（またはユーザー領域） | 選択 |
| モデル | `platformdirs` 配下 | 選択（**数 GB あることを表示**） |
| ジョブ | `platformdirs` 配下 | 選択（**文字起こし結果が含まれる旨を表示**） |
| ffmpeg | アプリケーションデータ配下 | 選択 |
| uv | ユーザー領域 | **削除しない**（他で使われている可能性がある） |

- 各項目のサイズを表示する
- **ジョブには文字起こし結果が含まれる**ため、削除の意味を明示する
- 削除しなかったものの場所を、完了時に表示する

## Step 3 — SmartScreen への対応

未署名の実行ファイルは、Windows で警告が出ます。

### 実施内容

1. **警告の内容と回避手順を README に記載する**
   - 「詳細情報」→「実行」の手順
   - なぜ警告が出るのか（署名がないため）を説明する
   - 警告を無視することの意味を、正直に説明する
2. **SHA-256 を公開する**
   - リリース時に配布物のハッシュを算出する
   - GitHub Releases の本文に記載する
   - **利用者が検証する手順を README に記載する**
     （PowerShell の `Get-FileHash` を使う）
3. **`docs/リリース手順.md` に、ハッシュ算出と公開を組み込む**

### 署名を差し込める構造

ビルドスクリプトに、署名ステップを追加できる箇所を用意してください。

- 環境変数や引数で証明書を指定できる形
- 指定がなければ署名せずに続行する
- **今回は署名を実行しません**

## Step 4 — ビルドの自動化と再現性

### ビルドスクリプト

`build.ps1`（または相当のもの）を作成し、以下を1コマンドで実行できるようにします。

1. GUI 環境の依存を同期する
2. PyInstaller でビルドする
3. Inno Setup でインストーラーを作る
4. SHA-256 を算出する
5. 出力先に配置する

### 要件

- **冪等であること**
- ビルド前に前回の成果物を消すか、上書きするかを明確にする
- 失敗した箇所が分かるエラーを出す
- **バージョン番号を一箇所から取得する**
  （`pyproject.toml` と実行ファイルとインストーラーで食い違わないようにする）
- 前提ツール（PyInstaller、Inno Setup）が無い場合、導入方法を案内する

### CI との関係

**CI でインストーラーをビルドするかを判断してください。**

- Inno Setup は Windows でのみ動作します
- ビルドに時間がかかります
- タグを打ったときのみ実行する、という選択肢もあります

判断と理由を記録してください。**無理に CI に載せる必要はありません。**

## Step 5 — 実機での検証

### 検証環境

**ビルドしたインストーラーを、実際にインストールして確認してください。**

Phase 5d 事前準備で作成したクリーン環境の手法が使えるはずです。
`docs/Phase5d事前準備.md` の記録を参照してください。

**既存の環境を壊さないでください。**
インストーラーはユーザー領域に書き込むため、既存の設定やモデルと
干渉する可能性があります。事前に影響範囲を確認してください。

### 検証項目

1. **インストール**
   - 管理者権限なしで完了する
   - ショートカットが作られる
   - ライセンスと追加ダウンロードの案内が表示される
2. **初回起動**
   - GUI が起動する
   - **Phase 5c のウィザードが起動する**
   - ウィザードを通じて、文字起こしができる状態に到達する
3. **通常利用**
   - 2回目以降はウィザードが出ない
   - 文字起こしが実行できる
   - 結果を閲覧できる
4. **アンインストール**
   - 削除対象を選択できる
   - 選択した対象が実際に削除される
   - **選択しなかった対象が残る**
   - 残ったものの場所が表示される
5. **再インストール**
   - アンインストール後に再度インストールできる
   - 残していた設定やモデルが再利用される

### 記録すること

- 各項目の合否
- インストーラーのサイズ
- インストールから文字起こし可能になるまでの所要時間
- 初回起動時のダウンロード量
- **利用者体験上の気づき**
- 実機で検証できなかった項目と理由

## 実装上の注意

### 作業環境

**作業機は Intel 機です。**

- `cuda` プロファイルは検証できません
- インストーラーの動作確認は `intel` または `cpu` で行うことになります
- **CUDA 環境での初回フローは未検証として記録**してください

### 事前準備の申し送り

`docs/Phase5d事前準備.md` に「5d へ向けた申し送り事項」があります。
**必ず確認し、対応または記録してください。**

特に以下は 5d に直結します。

- uv 未導入からの実 PATH 書き込みが未検証である点
- device 診断表の罫線文字化けが未解決である点

### 機密データ

- 実データを検証に使わない（合成音声を使うこと）
- 文字起こしの内容を記録しない
- **スクリーンショットを撮る場合、他のウィンドウが写り込まないよう注意する**
- ビルド成果物をコミットしない

### 破壊的変更への配慮

- 既存の venv、モデル、設定、ジョブを壊さない
- インストーラーの検証で既存環境に影響が出ないことを事前に確認する
- Phase 5a・5b・5c の機能を壊さない
- `setup.ps1` と `run.ps1` は引き続き動作すること

### コミット

- ブランチ `feature/phase5d-installer`
- Step 単位でコミットする
- `git push` は実行しない
- **ビルド成果物（exe、インストーラー）をコミットしない**
- `.gitignore` にビルド出力先を追加する

---

## 禁止事項

- 配布物に推論コアや torch を含めること
- プロファイル venv をインストーラーに含めること
- 管理者権限を要求すること
- 初回のダウンロードを事前に案内しないこと
- アンインストールで uv を削除すること
- ジョブ削除の意味を説明せずに削除させること
- 開発環境外での動作を確認せずに「完了」と報告すること
- 実機でインストールを確認せずに「完了」と報告すること
- 既存の環境を壊すこと
- ビルド成果物をコミットすること
- `要件定義.md` を更新せずに仕様を変えること

---

## 不明点があった場合

1. `要件定義.md` と事前準備の申し送りを優先する
2. ビルド構成の細部は判断してよい。判断と理由を記録する
3. 判断できない場合、安全側（既存を壊さない側）に倒し、記録する
4. 設計の変更を伴う判断は、実装前に `要件定義.md` へ反映する
