## Step 1 — A-2: `.format-chip` の横スクロール

### 既知の情報

引継ぎ文書に **`position: relative` の欠落**が原因と記録されています。

絶対配置された要素が、意図した親要素ではなく、より外側の要素を基準に配置されているため、
はみ出して横スクロールが発生していると推定されます。

### 作業

- **記録された原因が正しいかを確認してから修正してください。**
  CSS の問題は、原因が複数重なっていることがあります
- 修正後、**他のレイアウトに影響が出ていないこと**を確認する
- ウィンドウ幅を変えても横スクロールが発生しないこと

### 注意

**この修正で、他の絶対配置要素が動く可能性があります。**
`position: relative` を追加すると、その要素が新しい配置基準になるためです。

**同じ親の中に他の絶対配置要素がないかを確認してください。**

## Step 2 — A-5: バージョン表示のずれ

### 症状

GUI が表示するバージョンが、実際のバージョンと一致していません。

### 調査

**どこがずれているかを特定してください。**

バージョン情報を持つ場所が複数あります。

- パッケージのメタデータ
- インストーラーが埋め込む ProductVersion / FileVersion
- GUI が表示する値
- **`README.md` と `README_en.md` の冒頭の記述**

### README の記述（重要）

**日英どちらの README も、冒頭に古い記述が残っています。**

> 開発版: `0.1.0`（未 release）。直近の公開 snapshot は `v0.0.1` です。

実際は 0.1.22 で、`main` は push 済みです。**利用者がどの版を使っているか判断できません。**

**これも A-5 の一部として修正してください。**

### 対処の方針

**バージョンの出所を一元化することを検討してください。**

複数箇所に手書きされていると、更新漏れが再発します。
`変更履歴.md` の更新に伴って自動的に反映される形が望ましい。

**一元化できない箇所がある場合、その理由と、更新漏れを防ぐ手段を記録してください。**

### 回帰テスト

**バージョンの不整合を検出するテストを追加してください。**

パッケージのバージョンと、GUI が表示する値、README の記述が一致することを検証します。
**版を上げたときにテストが失敗すれば、更新漏れに気づけます。**

## Step 3 — A-7: 入出力ディレクトリの独立記憶

### 症状

入力と出力の既定ディレクトリが独立して記憶されていません。

### 作業

- 入力ディレクトリと出力ディレクトリを、**それぞれ独立して記憶する**
- 前回使用した値を次回の既定として提示する
- **どちらか一方を変更しても、他方に影響しない**

### 保存先の注意

**GUI 設定には、利用者のファイル履歴を保持しない方針があります。**

`README.md` に記載があるはずです。**ディレクトリのパスを保存することが、
この方針に抵触しないかを確認してください。**

抵触する場合、**方針を優先してください。**利便性より機密性を取ります。
その場合、代替案（セッション内のみ記憶する等）を検討し、判断を記録してください。

**判断に迷う場合、保存しない側に倒してください。**

### 本作業で追加する項目

**本作業で実機確認が必要になった項目を追記してください。**

想定されるもの:

- **A-2 の修正後のレイアウト確認**（CSS は自動テストが難しい）
  - 各画面で横スクロールが発生しないこと
  - ウィンドウ幅を変えても崩れないこと
  - 他の絶対配置要素が意図しない位置に移動していないこと
- A-5 のバージョン表示が正しいこと（**exe で確認**）
- A-7 の入出力ディレクトリが独立して記憶されること

**上記は想定です。実際に確認が必要なものを判断して追記してください。**

### 記載の形式

既存の項目に倣ってください。各項目に以下を含めます。

- **背景**（なぜ AI 側で確認できないのか）
- **手順**（実機の前で見て実行できる粒度）
- **合格条件**（チェックボックス形式）
- どの版・フェーズで追加されたか

**「動作確認」のような曖昧な記述にしないこと。**

### 環境の章

既存の章構成に従って配置してください。

- **A章: Windows Sandbox** — インストーラーの挙動
- **B章: Core i7 機** — GPU 非搭載環境固有
- **C章: 環境を問わないもの** — 現在は空。本作業の項目はここに入る可能性が高い

### 今後の運用（記録する）

**`要件定義.md` または `AISTATE.md` に、以下を運用として記録してください。**

> 実機確認が必要な項目が生じた場合、**その作業と同じ単位で
> `ユーザー確認事項.md` へ追記する。**後回しにしない。
> 確認済みの項目は削除せず、結果を記入して残す。

これは4文書（README / 変更履歴 / 要件定義 / AISTATE）の更新義務に準じる扱いですが、
**確認項目が増えた場合のみ更新すればよい**という点で異なります。
